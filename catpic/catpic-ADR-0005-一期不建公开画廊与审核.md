# ADR-0005：一期不建公开画廊与审核，likes 表休眠

初始 schema 建了 `likes` 表与公开读 RLS，隐含"公开作品社区"的产品形态。但一期没有管理员（见 ADR-0003），而任何公开列表都会立刻引入内容审核、举报与下架义务。

决定：一期的"公开"只到**可分享的只读链接页（`/p/<id>`）**为止。不做浏览他人作品的列表页，不做好友/关注，`likes` 表一期**保留但休眠**（不写不读）。

相关：[[catpic-术语表]] · [[00-catpic索引]] · [[catpic-ADR-0004-原图永远私有定稿默认私有需显式发布]]

## 考虑过的选项

- **开关 + 画廊页**：社区感强，但立刻需要审核/举报/下架，与"没有管理员"直接冲突。
- **开关 + 画廊 + 个人主页/关注**：一期连登录界面都没有，属于凭空造社区。

## 后果

- `likes` 表与公开 RLS 策略在一期是**死码**。留着是为了将来加列表页时不必重写 schema；读者不要因为看不到使用点而删除它。
- 一期没有浏览型先容列表，因此不承担"持续运营一个内容广场"的义务；但**公开分享同样有内容风险**，只是暴露面更小。本期采取的做法是控制发布人数与分享范围，而不是声称风险不存在。
- 分享页与未来的画廊卡片应复用同一个展示组件，使"加列表页"是新增页面而非重做。
- 传播依赖分享链接，因此分享页的 OG 卡片/预览图属于一期范围内。
