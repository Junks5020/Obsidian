# ADR-0006：一期邀请制小范围公测，额度用 credits 预扣、失败退回

一期没有真实模型成本模型、没有管理员（ADR-0003）、没有审核动作（ADR-0005）。若开放公网注册，成本与内容风险都不可控；若只给作者自己用，则无法验证"用户是否满意产物"这个唯一重要的假设。

决定：一期为**邀请制小范围公测**（数十到数百人）。生成额度复用 `profiles.credits`：邀请时赠送，每次生成**预扣 1，失败退回**；不建充值入口、不建流水表、不接支付。扣减与退回必须由数据库函数完成（事务 + 行锁 + 幂等），不得在应用层 read-modify-write。

相关：[[catpic-术语表]] · [[00-catpic索引]] · [[catpic-ADR-0005-一期不建公开画廊与审核]]

## 考虑过的选项

- **完全不管额度**：邀请制只限制人数，不限制单人，一个脚本就能清空模型预算。
- **代码层日配额**：多一套概念，且同样需要并发安全，收益低于复用已有 `credits`。
- **完整积分体系（流水 + 充值 + 支付）**：没有付费渠道时是死代码；流水表的价值在对账，当前无账可对。

## 后果

- 退款判据是 `generations.status`，不需要新表；但**同一条记录只能退一次**，幂等键必须存在。
- 邀请码本身是一期限流器：发放量即成本上限。
- 将来接入真实收费时，`credits` 字段与扣减点都不需要改，只需新增流水与充值路径。
- 额度对用户是可见的（剩余次数），因此 UI 必须展示余额与失败退款结果，否则会被视为吞额度。
