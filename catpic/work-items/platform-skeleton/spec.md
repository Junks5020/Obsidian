# 平台骨架一期规格

宠物照片动漫画平台的第一个可交付版本：跑通「上传 → 生成 → 出定稿 → 历史 → 发布」闭环，生成能力经适配器接入，真实模型可暂缓。

相关：[[catpic-术语表]] · [[00-catpic索引]] · [[catpic-ADR-0002-平台骨架先行生成能力以适配器保留]]

## 一、范畴：5 个页面

| 页面 | 内容 |
|---|---|
| `/login` | 邮箱 6 位验证码；邀请码兑换内嵌本页，不单开页面 |
| `/` | 单图上传 + 风格选择（封面卡片）+ 生成按钮；未登录引导登录 |
| `/g/[id]` | 任务页：轮询状态、原图/定稿左右对比、重试、下载、发布开关、失败原因（含输入不合格被拒） |
| `/me` | 我的定稿列表，按时间倒序 |
| `/p/[id]` | 已发布定稿的只读分享页，含 OG 预览卡片 |

**明确不做**：画廊/浏览他人作品、点赞、关注、个人主页、支付与充值、多图输入、管理后台、多语言、密码找回（OTP 替代）、AI 之外的编辑工具（裁剪/美颜/加字）、人脸硬拒。

未记 ADR 但已定的决策：
- 认证改为邮箱和密码；注册验证邮箱、找回或首次设置密码使用邮件链接。密码恢复不要求输入邮箱验证码；实际邮件与密码重置闭环待验证。既有账号保留原身份及额度。
- 输入契约：技术校验（类型/大小/最小分辨率/EXIF 纠正）+ 内容判定（须含单一主体宠物，不合格当场拒且不扣额度）。
- 一期输入只允许 1 张，但**存储字段按数组设计**；UI 上的单图是**有意的一期约束**，代码中不得当作"已支持多图"。
- 一期**不做强度档**：压低变量数，避免失败归因不可定位。
- **占位产物用基于用户原图的确定性滤镜**（边缘/降饱和/色阶），并在 UI 显式标注"占位效果，未接入真实模型"。不得使用别人的示例图冒充转换结果，不得让占位图在文案上暗示为真实生成。
- 占位期内**内容判定也 mock**：不调用视觉模型，文案上诚实说明"未检测"。
- **占位标识必须覆盖所有出口**：任务页、历史列表、分享页 `/p/[id]`、OG 描述、以及**下载文件名/文件本身**。占位产物不得用于证明未来模型的质量或保真能力。

## 三、Schema 变更（相对 `0001_init.sql`）

- `styles`（新增）：`slug` / `name` / `cover_path` / `prompt` / `enabled` / `sort`。公开只读且仅 `enabled = true`；seed 维护；不物理删除。
- `generations`：
  - 新增 `input_paths text[]`（一期恒为长度 1）、`style_id` → `styles`（`on delete restrict`）
  - `is_public` 默认改 `false`；新增 `published_at`
  - 新增 `processing_started_at`（超时回收判据）
  - 新增 `reject_reason`（输入不合格的终态说明）
  - `status` 枚举新增终态 `rejected`
  - `prompt` 改为由所选风格模板组装的产物，不再接受用户自由输入
- `invites`（新增）：`code` / `credits` / `redeemed_by` / `redeemed_at` / `created_at`。

## 四、隐私与存储

已确认的契约（本次采访内确定）：

1. 原图只有本人可读。
2. 定稿默认为私有，用户主动发布后才可被他人通过链接访问。
3. 未发布的图在分享页不可达（一律 404，不做"有权限就看得到"的分支）。

**已定的存储结构**（2026-10-29，03 落地）：两个 `public = false` 私有桶 `generation-inputs` / `generation-outputs`，路径 `<uid>/<inputs|outputs>/<file>`；首段即所有者，storage 策略与 `create_generation` 的路径归属校验用同一规则。

**已定的发布机制**（2026-10-29）：**不复制公开副本**。`/p/[id]` 服务端校验 `published_at is not null` 后，按需签发短时效 URL（约 10 分钟）。撤回发布 = 停止签发，语义立刻成立；这也让 ADR-0004 里"撤回无法追回缓存"这条从"缺陷"变成"只影响已发出的那次链接"。OG 预览图用固定路径 `/p/[id]/image` 重定向到现签的 URL，避免把会过期的签名写进 `<meta>`。

已排除：**"公开桶里的私有前缀"不是方案**——公开桶内任意路径可被匿名读取。

撤回发布只能尽力而为：已进入浏览器缓存、CDN、第三方 OG 抓取的副本无法追回。不得向用户承诺"撤回即彻底失效"，需在发布确认处明示。

## 五、额度与写入安全（强制性，存在现成漏洞）

现有 `0001_init.sql` 在引入 credits 后变成严重漏洞：

1. `profiles are updatable by owner` 允许用户 `update` 自己的**任意列**，包括 `credits` —— 等于额度免费。
2. `users update own generations` 允许用户 `update` 自己记录的任意列，包括 `status` —— 等于可伪造"失败"骗取退款。

必须覆盖的不只是 UPDATE，而是所有写入面：

- **UPDATE**：客户端不得直接写 `credits`、`status`、`image_path`、`style_id`、`published_at` 等敏感列。
- **INSERT**：不得能自行创建高额度 profile（`profiles` 自建路径也要封），也不得能伪造任务行绕过扣额。
- **RPC**：扣额/退款函数不得接受客户端自报的余额或终态，必须自己读、自己写；执行权限需按角色收紧。
- **Storage**：上传路径必须绑定 `auth.uid()`；不得能写入他人目录，也不得能在私有区以外写入。
- **邀请码**：兑换必须原子化（同一码只能成功一次），重复兑换、并发兑换均被拦住。

原子性要求（两组分开，不可合并）：

1. **创建任务 + 预扣额度**必须原子：不得出现扣了钱没任务，或有任务没扣钱。
2. **写终态 + 退款**必须原子，且退款凭据是**服务端写入的终态**，不是客户端可改的字段。

上述每一条均需用越权/并发测试实测，不接受"代码看起来对"。

## 六、验证要求

1. **额度可信**：失败、被拒、超时回收三种路径都不扣额度；重复退款、并发退款均被拦住；用户无法自行改额度。
2. **隐私**：未发布状态下，用匿名会话与另一个登录用户分别尝试直连原图与定稿，均失败。
3. **主体一致 / 结构对齐**：属产品验收，**候选指标**为轮廓 IoU、姿态关键点一致性、"同一只宠物"人眼通过率；阈值待真实产物实测后确定，尚未确认。
4. **兜底可见**：卡死记录能被定时任务回收，用户看到明确失败原因而非永久转圈。
5. 每个任务完成前必须实际运行受影响路径（构建 + 本地手测），不得只读代码判定通过。

## 七、待验证的实现假设（不是已确认事实）

- 托管商 serverless 的最长执行时长、请求结束后的后台执行能力、定时任务机制与套餐限制 —— 实施前查官方文档确认。
- Supabase 自带邮件服务的发送额度与送达率；自有 SMTP 是否必须配置。上线前必须实测一次真实投递到 QQ/163 邮箱。
- 签名 URL 的时效上限与刷新策略。
- 真实 image-edit 模型的单张耗时与成本。

## 八、开放问题

- ~~真实模型暂缓时，产物从哪来？~~ 已定：基于用户原图的确定性滤镜占位，显式标注。
- 风格种子数据的首批清单：几个、哪些画风、封面图来源。
- `/p/[id]` 与 OG 卡片在国内访问场景下的可达性未验证。
- 占位滤镜与真实模型产物的视觉差异会造成预期错位（用户可能以为最终就这么丑）；需在真实模型接入时单独安排一次预期重设，而不是默默替换。
