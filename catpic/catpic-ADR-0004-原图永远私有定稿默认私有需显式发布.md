# ADR-0004：原图永远私有，定稿默认私有且需显式发布

初始 migration 让 storage 桶 `generations` 公开可读、`generations.is_public` 默认 `true`。但本产品的输入是用户的私人宠物照片，画面里可能带人脸、住址等背景信息——默认公开是事故而非取舍。

决定：**原图永远私有**（只允许本人读取）；**定稿默认私有**，由用户显式「发布」后才可被他人通过链接访问。`is_public` 保留但默认改为 `false`，公开读的条件收紧为"已发布"。具体的公开副本与鉴权读取机制留待设计，不在本 ADR 内定死。

相关：[[catpic-术语表]] · [[00-catpic索引]] · [[catpic-ADR-0003-风格库存于数据库由seed维护不建运营后台]]

## 考虑过的选项

- **全私有**：最安全，但让已建好的 `likes` 表与公开读 RLS 变成废码。
- **维持现状（原图与定稿都进公开桶）**：任何拿到 URL 的人都能看到用户家客厅和门牌号。
- **原图私有 + 定稿默认公开**：保留了画廊的增长效果，但把"默认公开"这颗炸弹留在原地——宠物图同样可能拍到人，且用户会毫无察觉。

## 后果

- 原图必须放在**真正的私有桶**（`public = false`），不能靠"公开桶里的私有前缀"——公开桶中任何路径都可被匿名读取。定稿同样存私有区，通过带时效的签名 URL 展示。
- 「发布」是用户动作，因此需要 `published_at` 之类的状态；公开读 RLS 条件从 `is_public` 收紧为"已发布"。
- 「发布」是用户动作，因此需要 `published_at` 之类的状态；公开读 RLS 条件从 `is_public` 收紧为"已发布"。
- **实现采用"按需签发"而不是"复制公开副本"**（2026-10-29 定）：已发布定稿仍在私有桶，`/p/[id]` 每次请求现签短时效 URL。撤回 = 停止签发。这样"撤回后旧链接失效"在平台侧成立；已进入浏览器缓存或第三方抓取的副本仍无法追回，这一点照旧要如实告知用户。
- 默认私有会降低分享率，需要产品侧补偿（例如发布激励），而不是靠改默认值。

## 实施后补充（2026-10-30）

按需签发方案落地时暴露了归属校验的真实缺口：`create_generation` 最初只比对路径首段，`<uid>/../<他人uid>/inputs/x.jpg` 可以过检，而下游签名与下载用 service_role **无条件信任库里的字符串**。现已改为整串正则 + 显式拒 `..`，并在应用侧用 `isOwnedObjectPath` 二次校验。

**通用原则**：凡是"数据库里存路径、服务端凭该路径取对象"的设计，都必须把路径当成**不可信输入**重新校验，不能因为它来自自己的表就信任。

## 实施后补充之二（2026-10-30）：公开桶无法用 SQL 删除

`0005` 原计划 `delete from storage.buckets` 清掉 `0001` 的公开桶，但 Supabase 的 `storage.protect_delete()` 会拒绝（42501），而本地裸 PostgreSQL 允许——同一份迁移在两边行为不同。

改为「把桶置 `public = false` + 清空它上面的全部策略」。安全效果等价：**没有策略的私有桶，客户端完全不可达**。要彻底删掉这个空桶只能在 Dashboard 的 Storage 页面手动删除。
