# ADR-0003：风格库存于数据库，由 seed 维护，不建运营后台

「风格」是动漫画的有限枚举目标，运营希望能调整。仓库里 `profiles` 没有 `role` 字段，也没有任何登录页面，因此「谁是管理员」这个前提尚不存在。

决定：风格作为数据库表存在（可上下架、排序、改提示词模板），但**一期不建任何管理界面**；数据由 migration 里的 seed 与 Supabase Dashboard 手工维护。风格**只能下架（`enabled = false`），不物理删除**，历史定稿靠外键引用它。

相关：[[catpic-术语表]] · [[00-catpic索引]] · [[catpic-ADR-0002-平台骨架先行生成能力以适配器保留]]

## 考虑过的选项

- **代码常量**：零表结构变更，但运营改一次 prompt 要发版。
- **项目内 admin 页面**：需要引入 `role`、路由守卫、写策略与审计，等于一期养出一个权限子系统，而一期"运营"就是作者本人。
- **service_role 半自动页面**：把 `role` 换了个形式又回来了，且 `SUPABASE_SERVICE_ROLE_KEY` 目前连配置都没启用。

## 后果

- 读接口按"只读 `enabled = true`、公开可读"设计，与将来有后台时的读路径一致；后台只是新增写路径，不需要改读路径。
- 没有后台 ⇒ 没有 `role` 字段 ⇒ 一期不存在管理员概念。这条是**有意的缺席**，不是遗漏。
- 物理删除风格会导致历史定稿失去风格名；若将来确需删除，产物必须冗余存风格名快照。
