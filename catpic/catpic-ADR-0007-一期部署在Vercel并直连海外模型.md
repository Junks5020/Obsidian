# ADR-0007：一期部署在 Vercel 并直连海外模型

数据层已是 Supabase（海外）。把 Next.js 搬到国内并不能搬走数据往返延迟，只会多养一条出网代理链路；而只把数据库也国内化才算真正解决，那等于重做数据层。一期是邀请制内测，用户可沟通，延迟与偶发不可访问可被容忍。

决定：一期部署 **Vercel + Supabase + 直连海外 image-edit 模型**（Gemini image-edit / OpenAI `gpt-image-1` 等，经生成能力适配器）。不搭代理、不做国内化。

相关：[[catpic-术语表]] · [[00-catpic索引]] · [[catpic-ADR-0001-生成路线由通用大模型主导]]

## 后果

- **切换触发条件**：内测用户出现"页面打不开"，或首屏可交互时间持续 > 5s，则重新评估部署形态（其中一种选项是连数据层一起国内化）。具体阈值与可行性待实测后确定，不预先当结论。
- 宿主环境的函数执行时长上限、套餐限制与后台任务机制必须**在实施前查当前官方文档确认**，不得沿用本文起草时的印象值。
- 长耗时生成不能依赖请求内同步等待（具体限制参见 ADR-0008 与官方文档）。
- 模型调用必须走适配器，禁止在产品代码中直接依赖任何单一模型 SDK；换模型或换部署形态时只改适配器与配置。
- 模型侧的成本与合规（数据是否出境）由作者在邀请说明中披露，一期不做自动化合规流程。
