# ADR-0002：平台骨架先行，生成能力以适配器保留

仓库里已有的 `supabase/migrations/0001_init.sql` 是**文字生图**的形状（`prompt` / `negative_prompt` / 单值 `image_path`，无输入图），而产品是**图片到图片**的宠物动漫画。同时产品路线是"先把平台做出来，AI 换图保留"。

决定：**一期交付「上传 → 建任务 → 出定稿 → 历史」的平台骨架**，真实模型调用收敛到一个统一的生成能力适配器接口。一期真实模型暂缓，产物为**基于用户原图的确定性滤镜占位**，且必须显式标注。一期**一次任务恰好产出一张定稿**，因此请求与产物不拆表。

相关：[[catpic-术语表]] · [[00-catpic索引]] · [[catpic-ADR-0001-生成路线由通用大模型主导]]

## 考虑过的选项

- **展示/社区站先行**：没有产物的社区是空壳。
- **文字生图先行**：复用现有 schema 零改造，但交付了没被要求的功能。
- **冻结代码什么都不做**：只是"暂缓"的体面说法，没有推进。

## 后果

- `generations` 必须增加输入图字段，否则表结构无法表达产品的核心资产。
- 因为一期单产物，`generations` 一行同时承载请求与产物是可接受的；**若将来引入候选组，必须拆成请求 / 产物两个实体**——这条是有意的债务，不是疏忽。
- 生成能力适配器是一期唯一需要"可替换"的部件，产品流程不得直接依赖任何具体模型 SDK。
