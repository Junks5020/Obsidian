# 数据集树字段节点展示字段编码 - 开发计划

> [!summary] 需求一句话
> 报表设计器和打印模板设计器的数据集树中，字段节点展示格式由 `字段中文名` 改为 `字段中文名(字段编码)`（如 `合同编码(u_htbh)`）。纯展示变更，不影响选中、拖拽、属性配置等已有交互。后端已实现，本次只做前端。

## 1. 需求要点

- 字段编码 = 数据库表列名（如 `u_htbh`）。
- 树结构不变：仍为"数据集名称 → 字段"两级结构，仅字段节点显示文本变更。
- 打印设计器侧范围（详述中明确）：

| 数据集 | 改 | 说明 |
|---|---|---|
| 表单字段（内置） | ✅ | 按容器两级树展示，字段节点改格式 |
| 自定义数据集 | ❌ | 保持现状 |
| 流转历史（内置） | ❌ | 11 个系统预定义字段，无歧义 |
| 流程确认事项（内置） | ❌ | 5 个系统预定义字段，同上 |

- 勾选"显示标题"并拖拽时，写入单元格的标题**不含**字段编码。
- 字段属性面板、已绑定单元格中已存储的字段标识不受影响。
- 需同步 6.5.2 版本。

## 2. 代码现状（探索结论）

### 2.1 两个设计器共用同一组件

- 共用组件：`src/components/report/dataSetList/dragCollapse/index.tsx`（`DragDataSetCollapsePanel`，antd Collapse 手风琴，非 Tree）。
- 引用方：
  - 报表设计器 `src/pages/TableManager/design/components/leftAddDataSet/index.tsx:112`
  - 打印设计器 `src/pages/PrintManager/design/components/leftDataSetList/index.tsx:144`
- 字段节点渲染（当前唯一显示处）`dragCollapse/index.tsx:145-149`：

```tsx
const SortableItem = SortableElement(({ value }: { value: dataSetField }) => (
  <div className="dragItem">
    <div>{value.fieldShowName ? value.fieldShowName : value.fieldId}</div>
  </div>
));
```

- 字段类型定义：`src/components/report/dataSetList/types.ts:14-24`，已有 `fieldShowName / dbFieldId / dbFieldName / fieldId / fieldName / realFieldId` 等属性。
- 拖拽数据 `collection`（`dragCollapse/index.tsx:136`）是字段全量属性 JSON，**不含节点显示文本** → 改显示文本天然不影响拖拽绑定数据。

### 2.2 打印设计器侧

- 内置数据集字段来自 `getListField`，经 `src/pages/PrintManager/design/service.ts:20-37` 的"负负得正"交换：交换后**字段编码 = `fieldName`**（同时备份在 `realFieldId`），中文名 = `fieldShowName || fieldId`。
- 数据集类型区分标识只有 `dataSetSource`：`0`/空 = 自定义数据集；非 0 = 内置数据集（`dragCollapse/index.tsx:47`、`leftDataSetList/index.tsx:97`）。
- ⚠️ 前端**没有**区分"表单字段 / 流转历史 / 流程确认事项"三种内置数据集的标识，只能按 `name === '表单字段'` 或后端 `dataSetSource` 具体取值判断（仓库中查不到取值定义）。
- mock：`mock/print/getListField.ts` 存在，但 `mock/api.ts:12` 中注册被注释；且 mock 字段对象缺 `fieldShowName`，本地验证需补数据或走真实后端。

### 2.3 报表设计器侧

- 数据集均来自 `reportDetail.dataSetIds`（即自定义数据集，`leftAddDataSet/index.tsx:74-89`），字段接口 `/dataSet/listDataSetField(s)`。
- 字段编码候选属性：`dbFieldId`（类型定义注释层面最像"数据库列编码"），但需与后端确认真实返回的是哪个属性。
- 需求功能详述只列了打印设计器的范围表，报表设计器默认理解为**所有数据集字段节点都改**（待确认）。

### 2.4 "显示标题"拖拽

- 勾选框：`src/components/report/dataSetList/titleSetting/index.tsx:44-46`。
- 拖拽结束时标题文本来源：`src/components/report/dataSetList/dragWrapper/index.tsx:237`（整数据集）和 `:272`（单字段），均传 `field.fieldId`，经 `dragWrapper/utils.ts:96-110` 的 `setTitleTDMeta` 写入。
- 即标题用的是 `fieldId` 而非节点显示文本，理论上不会带上编码；但需验证报表设计器侧 `fieldId` 是否就是中文名（复杂数据集中"显示名称"是 `fieldShowName`，见 FieldSet 组件），必要时这两处改为传显示名。

## 4. 风险与待确认事项

1. **内置数据集区分标识缺失**：前端无法区分"表单字段"与另外两个内置数据集，需后端给出 `dataSetSource` 取值定义或新增标识字段；临时方案是按 `name === '表单字段'` 匹配（脆，不推荐上线）。
2. **报表侧编码属性未确认**：`dbFieldId` 仅是类型定义层面的最佳候选，mock 数据中为 null，必须以后端真实返回为准。
3. **"按容器两级树"**：需求描述表单字段"按容器两级树展示"，但前端目前所有数据集字段都是平铺渲染；`tableName`/`tableShowName` 属性已预留。需确认这是后端分组返回的现状描述，还是隐含新的分组渲染工作（本计划暂按"现状已如此、仅改显示文本"处理）。
4. **mock 不完整**：`listField` 的 mock 注册被注释且字段缺 `fieldShowName`，本地开发验证需补 mock 或连真实后端。
5. **共用组件影响面**：`dragCollapse` 为两个设计器共用，改动务必按场景加条件，避免打印侧自定义数据集被误改。
