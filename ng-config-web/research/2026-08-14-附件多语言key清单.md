## 翻译机制（关键前提）

- **字段 `label`、字段集 `title`**：`Form`/`FormSet` 组件支持 `langKey`，走 `core.getPageLang()[langKey] ?? originLabel` 自动查表；字段 `langKey` 默认取 `name`（仅附件存储配置/数据迁移适用；附件预览页无 Form，全部手动接入）。
- **`help`、`placeholder`、下拉 `options`、按钮、`message`、Panel 标题、表格列头、页面内静态文案**：**不会**自动翻译，需要手动用 `getLangText(key, 中文默认值)` 查表。
- 推荐仿照 `src/pages/workFlow/.../language.ts` 的成熟模式：`LangKey` 枚举 + `getLangText(id, defaultText)`，运行时取 `udp.getLang()` 平台语言词典，中文作兜底（`defaultTextMap`），平台词典缺失时页面不破。
- 语言字典来自后端：`SUP/GetLanguageInfoByBusType`、`SUP/Language/getLanguageMap?identity=xxx`，登录后经 `user.toolbarLang` + 页面实例 `getLang()` 合并；**自定义 key 需登记到平台语言包才能被翻译**。
- 动态文案统一用 `{0}` 占位符（workFlow 先例 `clewMsgInfo` 配合 `formatStringForArgs`），中英语序可能不同（如「{0}图标」→「{0} icon」）。
- **key 命名规则**：附件预览页新增 key 用 `fp` 前缀扁平 camelCase；附件存储配置/数据迁移沿用 2026-08-13 定稿 key（点分/扁平混合），`f1`/`f2`/`f3` 为代码写死的 `langKey` 不能改。
- **边界**：`PdfViewer` / `ExcelViewer` 是 iframe 嵌入服务端渲染的 `FilePreviewService/.../viewer.html`，其内部 UI 文案由服务端/第三方组件控制，**前端无法翻译**；`VideoViewer` 的 `react-doc-viewer` 已 `disableHeader`，无可见文案；`TxtViewer` 纯代码展示无文案。

## 结论 / 建议

1. **核心可复用的 key 是 `getCommonConfig` 那一套**（存储类型 label、地址类型、桶名、AccessKey/Secret、各种 help/描述），附件存储配置与数据迁移两页共享；`requestFail` 三页通用。
2. `label`/`title` 走 `langKey` 机制最省事（`Form`/`FormSet` 自动查 `getPageLang()`）；`help`/`placeholder`/`options`/按钮/`message`/Panel/表格列头及附件预览页全部静态文案必须**手动**接 `getLangText()`。
