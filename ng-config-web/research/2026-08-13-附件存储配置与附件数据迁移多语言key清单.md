# 附件存储配置 / 附件数据迁移_ng 多语言 key 清单

相关：[[00-ng-config-web索引]] · [[ng-config-web-术语表]]

## 页面定位

| 页面名 | 文件 | 说明 |
|--------|------|------|
| 附件存储配置 | `src/pages/SUP/Databaseinitconfig/index.tsx` + `utils.tsx` | 调 `attachConfig/getStorage` / `setStorage`（busType `16780`） |
| 附件数据迁移_ng | `src/pages/SUP/Datamigration/index.tsx`（复用 `Databaseinitconfig/utils.tsx` 的 `getCommonConfig`） | 调 `attachConfig/dataMigration` / `pauseMigrating` / `getMigrationInfo` / `pageMigrationInfo`（busType `16781`） |

## 翻译机制（关键前提）

- **字段 `label`、字段集 `title`**：`Form`/`FormSet` 组件支持 `langKey`，走 `core.getPageLang()[langKey] ?? originLabel` 自动查表；字段 `langKey` 默认取 `name`。
- **`help`、`placeholder`、下拉 `options`、按钮、`message`、Panel 标题、表格列头**：**不会**自动翻译，需要手动用 `getLangText(key, 中文默认值)` 查表。
- 语言字典来自后端：`SUP/GetLanguageInfoByBusType`、`SUP/Language/getLanguageMap?identity=xxx`，登录后经 `user.toolbarLang` + 页面实例 `getLang()` 合并。

## 结论 / 建议

1. **核心可复用的 key 是 `getCommonConfig` 那一套**（存储类型 label、地址类型、桶名、AccessKey/Secret、各种 help/描述），两个页面共享。
2. `label`/`title` 走 `langKey` 机制最省事（`Form`/`FormSet` 自动查 `getPageLang()`）；`help`/`placeholder`/`options`/按钮/`message`/Panel/表格列头必须**手动**接 `getLangText()`。
3. 动态 label 的字段（`storeUrl`、`storeUsername`、`storePassword`、`storeDBName` 等）**必须显式指定 `langKey`**，不能依赖默认的 `name` 当 key，否则不同存储类型会互相覆盖。
4. 建议仿照 `src/pages/workFlow/.../language.ts` 的模式，新建 `language.ts`（`LangKey` 枚举 + `getLangText`），把中文兜底文案集中管理，再配合后端语言字典 `SUP/GetLanguageInfoByBusType`（busType `16780`/`16781`）下发覆盖。
