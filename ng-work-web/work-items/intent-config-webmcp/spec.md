# 意图配置管理页只读 WebMCP

Status: ready-for-agent

相关：[[00-ng-work-web索引]]、[[ng-work-web-Agent工作流配置]]、[[ng-work-web-术语表]]

## Problem Statement

用户希望 Agent 能在已启动的前端、当前登录会话内，可靠地检索和查看“智能查单”管理页的意图配置，而不依赖逐个定位按钮和抓取页面文本。

该页面管理查单／问数意图配置，不执行实际查单。将两者混淆，会错误开放业务取数能力。现有页面还存在请求失败与空列表混同、未透传服务端总数、多页签缓存以及只读视图内部仍有编辑入口等问题，不能简单将服务函数或按钮直接包装成工具。

## Solution

为当前活动的意图配置管理页面提供四个只读 WebMCP 工具，复用当前用户的登录会话和权限。Agent 查询和导航行为与用户可见页面同步；读取详情与打开详情分离，前者不改变导航。

工具只提供意图配置检索与查看，不新增独立后端 MCP 服务，不执行配置中的取数地址，不扩大当前用户权限。默认返回基础信息及查询参数定义；高级配置需要显式请求且受当前权限限制。

## User Stories

1. As an 已登录用户, I want Agent 复用我的当前会话, so that 无需为工具重复登录。
2. As an 用户, I want 工具只提供我有权访问的能力, so that Agent 不会绕过管理页权限。
3. As an Agent 使用者, I want 获取当前页面的筛选、分页和加载状态, so that 能理解当前操作上下文。
4. As an Agent 使用者, I want 获取当前可用能力, so that 不会将不支持的操作视为可执行操作。
5. As an 用户, I want 按关键词检索意图配置, so that 快速找到目标意图。
6. As an 用户, I want 按全部、查单或问数筛选, so that 只查看所需类型。
7. As an 用户, I want 仅查看已启用意图, so that 聚焦当前可用配置。
8. As an 用户, I want 通过同一查询工具翻页和刷新, so that 无需学习额外工具。
9. As an 用户, I want Agent 查询时同步更新页面筛选与列表, so that 看得到它实际查询的范围与结果。
10. As an Agent 使用者, I want 获取结构化的列表摘要和稳定意图标识, so that 能可靠选择目标并继续读取详情。
11. As an Agent 使用者, I want 区分空结果和请求失败, so that 不会把系统故障解释成没有配置。
12. As an Agent 使用者, I want 知道分页总数是否可信, so that 不会错误宣称已读完所有配置。
13. As an 用户, I want 用户新查询优先于旧请求结果, so that 旧结果不会覆盖新页面状态。
14. As an Agent 使用者, I want 按意图标识读取结构化详情且不跳转, so that 分析配置时不会打断用户导航。
15. As an 用户, I want 默认详情包含基础信息与参数定义, so that 常规分析无需返回完整内部配置。
16. As an 用户, I want 高级配置必须显式请求且经过权限检查, so that 内部地址和完整提示词不会被默认返回。
17. As an 用户, I want Agent 能打开指定意图的只读详情, so that 可以亲自核对其分析依据。
18. As an 用户, I want 只读详情的所有内部编辑入口也受限制, so that 不会因工具导航进入可修改状态。
19. As an 用户, I want 工具只操作当前活动页面实例, so that 不会误操作隐藏缓存页签。
20. As an 用户, I want 切换、刷新和关闭页签后工具正确更新可用性, so that 不会残留指向过期页面的入口。
21. As an 用户, I want 登录失效和权限不足得到明确反馈, so that 能采取正确的恢复动作。
22. As an 用户, I want 配置中的地址和提示词只被当作数据, so that 查看配置不会触发任意请求或指令执行。
23. As an 用户, I want 未支持 WebMCP 时原有页面仍正常工作, so that 接入不会破坏人工使用。
24. As an 项目维护者, I want 个人规格和任务只保存在本地 Obsidian, so that 不会改变同事的 Agent 工作流。

## Implementation Decisions

### 业务范围与集成方式

- 以“意图配置管理”而非“实际查单”为领域边界。查单和问数都是本页可检索的意图类型。
- 采用页面内 WebMCP，复用现有会话、请求封装和权限链路；不另建后端 MCP 服务。
- 当前代码检索未发现已有 WebMCP 注册层。新增尽可能小的工具适配层，连接页面业务行为，不复制一套脱离页面的查询状态。
- 人工操作与 Agent 操作共享筛选、分页及结果状态。保留原有人工管理能力；本期工具及工具打开的只读视图不得提供写能力。
- 不改变后端数据模型，不新增数据库结构。

### 公开方法

| 方法 | 输入 | 对外行为 |
| --- | --- | --- |
| get_intent_page_context | 无 | 返回当前活动意图页面的筛选、分页、加载状态和可用能力；不发起业务写操作。 |
| list_query_intents | 可选 keyword、type、onlyEnabled、pageIndex、pageSize | 查询意图配置列表；承担筛选、翻页和刷新；等待实际加载结果并同步可见页面。 |
| get_query_intent | intentId；includeAdvanced 默认为 false | 返回指定意图的结构化配置详情，不改变页面导航。 |
| open_query_intent_detail | intentId | 打开指定意图的只读详情；返回明确的打开结果，而非仅表示已发出导航事件。 |

- 意图标识必须使用稳定业务标识，不以行号、名称或当前排序位置代替。
- 类型映射到页面支持的全部、查单、问数选项；输入 schema 必须明确枚举并兼容已有数据的历史类型表示。
- 对页码、页大小、意图标识和类型进行输入校验。工具页码口径与管理列表保持一致，不沿用实际查单链路的页码约定。
- 实施时将省略查询参数、清空筛选、刷新以及页码重置规则写清楚并用契约测试固定；这些细节尚未在会话中确定，不应暗中依赖控件偶然行为。

### 返回内容与高级配置

- 列表返回供选择意图使用的结构化摘要、稳定标识以及本次实际生效的查询范围。
- 默认详情包括名称、类型、状态、业务类型、描述及查询参数定义。
- 取数地址、完整提示词和样式等高级配置仅在 includeAdvanced 为 true 且当前用户获准查看时返回；不能将完整原始详情直接透传，再依赖调用方隐藏字段。
- includeAdvanced 不授予额外权限。若现有系统不能证明高级字段访问已获授权，应明确拒绝或说明不可用，而非静默扩大访问范围。
- 配置中的 URL、提示词及描述均为不可信业务数据；返回它们不意味着允许访问地址或执行其内容。
- 内置意图的展示状态在现有页面中有特殊转换；工具需明确状态口径，不将展示转换冒充后端原始状态。

### 结果、错误和并发

- 成功且无匹配记录、请求失败、登录失效、权限不足、无效输入、记录不可用和页面不可用应能被调用方区分。
- 触发刷新或导航不等于操作成功；在对应动作完成后返回结果，失败时给出明确反馈。
- 现有列表未保留真实服务端总数。未获得可靠总数时，明确表达总数未知，不能用当前页长度推算总数或宣称已遍历全部记录。
- 用户或 Agent 发起新查询后，较旧请求不得覆盖新页面状态；旧调用也不得把旧结果当作最新查询结果返回。
- 加载途中页面隐藏、销毁或切换时，应停止向过期实例提交结果，并向调用方明确说明该次结果不再适用。

### 页面生命周期与只读保证

- 工具绑定当前活动页面实例；同时考虑激活、隐藏、刷新、销毁，不仅处理挂载与卸载。
- 防止重复注册、残留注册及隐藏页签被错误选中；不向 Agent 暴露全局固定组件标识作为调用入口。
- 打开详情时保留页面所需的导航上下文，并以真正只读模式展示。
- 只读约束覆盖参数、样式及问数配置的内部新增、编辑、删除入口，而非只隐藏保存按钮。
- WebMCP 不可用或注册失败时，不破坏原有人工页面；不得将未注册状态报告为工具可用。

### 实施时需核实的技术细节

以下不是新增业务范围，也不是已验证事实：实施前应核对目标浏览器的实际 WebMCP API、工具结果封装及注册生命周期；核实可复用的页签激活信号、后端分页元数据和高级字段权限依据，并通过测试落实。

若环境不支持已约定能力，应报告阻塞，不静默改为独立后端服务或绕过权限。当前登录后页面尚未完成浏览器验证，已获得的功能依据主要来自源码调查。

## Testing Decisions

### 已确认的主要测试边界

以“Agent 调用公开工具 → 工具返回结果及页面可见变化”为主要入口，优先复用现有请求层作为后端替身边界。避免将大量组件内部函数或实现细节分别当作测试契约。

测试工具适配层与页面行为的集成，包括列表查询、详情读取、只读打开以及活动页签生命周期。注册 API 可使用最小宿主替身进行自动化验证，最终再通过支持 WebMCP 的真实浏览器验证宿主契约。

### 自动化验收

1. 四个工具具有清晰且可验证的输入 schema；非法输入不发起后端请求。
2. 读取上下文反映真实页面状态，不改变页面查询或导航。
3. 查询按关键词、类型和启用状态发送正确条件，返回结果与可见筛选、列表一致。
4. 翻页和刷新复用同一个查询工具，明确等待结果而非仅触发事件。
5. 请求失败、空列表、无权限、会话失效及无效详情能够区分。
6. 服务端未提供可信总数时，对外保持未知，不以当前页长度伪造。
7. 后发请求先完成时，先发请求不能覆盖页面，也不能被误当作最新结果。
8. 默认详情不包含高级字段；显式请求但权限不足时不泄露高级字段。
9. 读取详情不改变导航；打开详情显示指定意图，且所有编辑入口均不可用。
10. 页签隐藏、切换、刷新和销毁后，无重复或过期工具入口，也无跨实例更新。
11. 未支持 WebMCP 或注册失败时，人工页面仍可正常使用。
12. 列表和详情操作不调用保存、启停、删除或实际业务取数接口，不执行配置中的任意 URL。
13. 保留现有人工查询及管理能力，避免只读工具接入误伤正常授权操作。

### 现有测试参考与浏览器验证

仓库已有基于 Jest 风格的 API 错误信息测试，可参考其对错误输入与异步结果的断言方式；已配置的测试命令采用 umi-test。未发现现成 WebMCP 集成测试，不能将现有单测当作已覆盖本功能。

自动化测试使用可控响应验证外部行为，不依赖在线业务数据。最后在获得授权的已登录环境和支持 WebMCP 的浏览器中，验证工具发现、实际调用、筛选同步、只读详情以及页签切换。若登录或宿主能力阻塞，明确记录未验证项目，不宣称端到端完成。

## Out of Scope

- 实际查单、实际问数以及 robot 运行时业务取数链路。
- 新增、复制保存、修改、启用、停用、删除意图配置的工具。
- 导出、批量下载、审批及其他业务写操作。
- 执行配置中的取数地址、功能地址或提示词。
- 独立后端 MCP 服务、新认证体系或权限扩张。
- 将每个按钮或输入框逐一包装为工具。
- 全站通用 WebMCP 平台及无关页面改造。
- 将个人 AGENTS 入口、工作流配置、规格和任务提交或推送至远程。
