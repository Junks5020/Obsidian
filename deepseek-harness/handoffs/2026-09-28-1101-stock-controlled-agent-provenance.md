## Restore-provider design after independent review

Independent review accepted the direction with lifecycle conditions. `dsh-session` owns one effect-scoped restore-provider registration. Consumers request restoration only by Session ID, access intent (`read` or `write`), and cancellation signal. The Store invokes the provider; callers cannot pass seed events, headers, handles, or loader callbacks to the request. `dsh-session-persistence` registers its active backend through normal plugin composition, keeping `dsh-session` independent of concrete persistence. Provider registration is trusted Host configuration, not protection against arbitrary Host code.

The provider reads the validated stored header, event log, and inherited-event count. Read access closes its handle before returning; write access retains the exact write handle as provider-owned resource. The Store constructs the restored Session from that provider snapshot and privately records authority for the exact object. Failed construction releases the resource. A `SessionPersistence` consumer wrapper returns a Store-created restoration lease with the exact Session, raw stored events, deterministic crash-repair events, and the write resource when requested.

The Store computes `interruptedTurnClosers()` from raw persisted events before constructing the Session. Read access adds them only to the in-memory restored Session and observation. Write access returns them without appending. A side-effect-free preflight validates provenance, accepted-history continuity, repairs, and every unpublished suffix before the first write. Only then may AgentLoop append repairs and constructor suffixes through the retained write handle. `SessionStore.enter()` repeats the same checks immediately before publication. Rejected replacements must not mutate accepted-history indexes.

AgentLoop keeps write-handle ownership across its existing setup/publication transaction: the restore lease owns the handle until one explicit transfer, disposal is idempotent, the existing `StoredSession` writer receives the exact handle, and AgentLoop closes it on rollback or lifecycle disposal. The existing abort race remains around restore; an abandoned late restoration is disposed to release its handle. Read restoration closes before return and retains no handle.

`SessionObservationReader` uses read access after its existing revision check and retains no handle. It rechecks persistence revision after the coherent read and retries if the revision changed; it caches only the exact Store-authorized Session and repaired event view matching the stable revision. It also preserves the existing live-session recheck after asynchronous loading.

The pre-write regressions reject copied target history before writes or publication. The fresh-process stock regression persists source A and copied target B, rejects B through AgentLoop/StockAgentPolicy, verifies B's event log and revision are unchanged with zero adapter calls, then resumes A and persists a successful approved assistant response. A rejection without persisted-log comparison would not establish that an existing target stayed unchanged.

Cold fork construction now uses Store-issued unpublished preparation over the exact retained `SessionObservation` cut, passed into AgentLoop's existing persistence/setup/publication transaction. The controller does not reread the source by ID or authorize arbitrary seed arrays. This preparation alone does not imply a Session format change.

### Tool additional-context pipeline

`ToolRuntime.prepare()` snapshots arguments, runs `tools/pre-execute`, then applies monotonic guards. A guard denial returns a `post-result`; AgentLoop therefore calls `finalize()` and `tools/post-execute` even though neither the around-dispatch `tools/execute` waterfall nor the tool body ran. `finish()` bypasses post-execute for final results. On acceptance, post-execute contexts are combined with body/deferred contexts; a block drops those earlier contexts and retains only contexts attached by the blocking decision. `AgentLoop` appends the protected `tool/result` first, then splices accepted contexts into the next-step Inbox, where they are logged as Inbox and user-message events. PTC composites ferry nested contexts through `deferContext`; a stock-denied outer call cannot start those subcalls.

The Web base composition includes `repeat-tool-reminder` unless an upper layer disables it; the current patch stack does not. Its post-execute listener counts denied calls and creates a plugin-source `UserMessage`. The detailed reminder embeds canonical arguments supplied by the model (up to the configured preview cap), so the model can echo text from an approved stock disclosure into a distinct ordinary-ID message. A real Loader/AgentLoop test now persists and restores this message and confirms same-provider replay in the source. The supported session-reference route rejects the required-policy source. In the same Store, copying the reminder to an ordinary target appends it but dispatch ends in `POLICY_DENIED` after the Store indexes the source occurrence. After flushing that target and restoring only it into a fresh Store, a later trusted-Host follow-up reaches provider B with the copied reminder. This direct Host API test demonstrates that the in-memory owner index is not durable global attribution; it does not establish a supported product export path. ToolRuntime does not classify or authorize arbitrary plugin contexts. Full profile activation and the supported UI/admission route remain unverified; do not claim a universal additional-context barrier.

`dsh-web-app` registers `session-reference` and `file-reference-local`; it disables `agent-instructions`, `tool-skill`, `plan-mode`, `compaction-basic`, `tool-result-pruner`, and filesystem tools. The local file-reference service and its Session Controller endpoint return path candidates only; they do not read file bodies. StockToolPolicy restricts tool use, including `read`, but the ordinary prompt path still accepts user text and uploads. The stock Host patch adds `stock-analysis` under a trusted preset root and configures StockAgentPolicy to recognize that ID, while retaining `agent-presets.default: standard`; it does not globally select stock-analysis. The stock preset itself adds persona and StockToolPolicy. Base Goal/GoalRoundDriver and repeat-tool-reminder are present by manifest layering; runtime activation is not fully verified.
