# 规格：A 股与港股持仓工作台私有试点

相关：[[试点方案]] · [[../../research/2026-09-08-现有股票DSH插件功能调研]] · [[../../deepseek-harness-Agent工作流配置]]

## Problem Statement

当前客户使用同花顺查看行情，并在中信证券、国兴和长江证券等账户持有 A 股或港股。客户无法在不暴露券商凭证、不依赖云端记账、不接受自动交易或荐股的前提下，把手工维护的跨账户持仓、行情和风险规则放进同一个 DSH 工作流。

客户需要在 Windows 本机的 DSH Web 中建立当前持仓快照，检查市场、币种、行业和单标的集中度，查看受许可行情数据，并将经过审阅的最小数据范围发给已配置模型，以获得带来源和时间的风险备忘录。

## Solution

提供一个仅供当前客户私有试点使用的 DSH bundle 和专用 profile。该 profile 以独立根布局替换标准 Web 布局：左栏显示持仓与自选，中栏显示资产总览或标的详情，右栏继续承载原生 DSH Agent 会话。

插件仅在 Windows 当前用户的本机运行，并由标准 DSH Web 的 loopback 访问控制保护。它不读取、控制、抓取或嵌入同花顺，不连接中信证券、国兴、长江证券或其他券商，不导入对账单，也不下单。

用户手动管理账户、现金和当前持仓快照。唯一经客户选定并取得许可的行情供应商提供 A 股和港股的证券搜索、报价、日/周 K 线、行业、基本面、新闻或公告元数据以及 HKD/CNY 汇率。数据显示来源、更新时间和过期状态。

用户通过工作台生成可预览的 Agent 上下文草稿。只有用户审阅并发送后，草稿才进入 DSH 会话。Agent 不拥有账本读取或写入工具，且拒绝买卖、持有、目标价、仓位和收益建议。

## User Stories

1. 作为当前客户的账户本人，我想在自己的 Windows 用户会话中运行工作台，以便持仓数据不离开本机。
2. 作为账户本人，我想通过 Edge 或 Chrome 打开本机 DSH Web，以便不安装独立桌面应用。
3. 作为账户本人，我想看到首次使用风险说明，以便理解软件不构成投资建议且行情可能延迟或错误。
4. 作为账户本人，我想创建名称由我定义的账户卡片，以便区分中信证券、国兴、长江证券或其他手动账户。
5. 作为账户本人，我想为账户选择 A 股或港股市场和 CNY 或 HKD 本币，以便持仓和现金按正确币种计算。
6. 作为账户本人，我想手动填写可选现金余额，以便现金计入总资产且不被误认为证券持仓。
7. 作为账户本人，我想先选择市场并从行情供应商搜索证券，以便使用可验证的代码和名称建立持仓。
8. 作为账户本人，我想输入当前数量和每股综合成本，以便获得当前市值和未实现浮盈亏估算。
9. 作为账户本人，我想录入非整手数量，以便如实表示已有零股或特殊数量而非模拟下单。
10. 作为账户本人，我想修改当前持仓和现金，以便账本保持与我自己记录一致。
11. 作为账户本人，我想看到手动变更的时间和前后值，以便发现误改而不把变更记录误作真实交易流水。
12. 作为账户本人，我想在 30 天内恢复误删账户、持仓或自选，以便避免手工录入丢失。
13. 作为账户本人，我想在 30 天内立即清空最近删除，以便主动永久移除不需要的数据。
14. 作为账户本人，我想按账户查看持仓，也想跨账户查看汇总，以便识别整体风险。
15. 作为账户本人，我想将同一市场和代码的跨账户持仓合并计算，以便了解真实单标的集中度。
16. 作为账户本人，我想将 A 股和港股中同一发行人的不同证券分开显示，以便不错误消除市场、股份类别和汇率差异。
17. 作为账户本人，我想在人民币总资产中查看港股折算值，同时保留港币原币金额和汇率日期，以便区分股票波动和汇率影响。
18. 作为账户本人，我想看到现金作为独立类别，以便证券集中度的分母不会被夸大。
19. 作为账户本人，我想按市场、币种、行业和单标的查看集中度，以便识别我自己的风险暴露。
20. 作为账户本人，我想把无法取得行业分类的证券显示为未分类，以便模型和产品都不猜测行业。
21. 作为账户本人，我想维护自选但不把它算入资产或风险，以便关注对象不会被误作持仓。
22. 作为账户本人，我想在标的详情查看最新价、日/周 K 线和少量基础指标，以便结合我的持仓检查走势。
23. 作为账户本人，我想查看基本面、新闻和公告的标题、来源、时间和原始链接，以便自行核验而不依赖二次改写。
24. 作为账户本人，我想让可见数据默认每 15 秒刷新、离开页面暂停，并能手动刷新，以便控制请求量和数据新鲜度。
25. 作为账户本人，我想在行情延迟、过期、失败或限流时看到明确状态，以便不将旧价理解为新价。
26. 作为账户本人，我想由自己创建集中度、相对成本跌幅和价格等规则，以便提醒反映我的风险偏好。
27. 作为账户本人，我想在工作台打开时看到已触发规则及事实依据，以便检查而不接收后台推送或交易指令。
28. 作为账户本人，我想配置一家行情供应商和本机 API Key，以便工作台得到被允许使用的 A 股与港股数据。
29. 作为账户本人，我想在设置中只看到 Key 已配置和末四位，以便避免明文再次暴露。
30. 作为账户本人，我想在模型发送前查看将发送的字段和模型服务商，以便每次决定是否暴露该范围数据。
31. 作为账户本人，我想只发送所选标的或主动选择的全局摘要，以便 Agent 不能自行读取我的完整账户。
32. 作为账户本人，我想默认不发送账户名和券商名，以便模型分析不需要识别我的账户来源。
33. 作为账户本人，我想收到固定结构的风险备忘录，以便检查数据范围、集中度、规则、待核验事项和反方情景。
34. 作为账户本人，我想在每项 Agent 事实旁看到来源、数据时间和不确定性，以便判断它是否可用。
35. 作为账户本人，我想让 Agent 拒绝买卖、持有、目标价、仓位和收益问题，以便产品不变成荐股软件。
36. 作为账户本人，我想导出加密备份并在同一 Windows 用户环境恢复，以便迁移或灾难恢复。
37. 作为账户本人，我想在导出前理解忘记备份密码不可恢复，以便自行保存密码。
38. 作为账户本人，我想在插件更新前生成备份并在失败时保留旧版本和数据，以便试点升级可回滚。
39. 作为账户本人，我想导出不含账户、证券、持仓、成本、Key、提示词或模型回复的诊断日志，以便安全报障。
40. 作为试点维护者，我想锁定已验证的 DSH、插件、Edge 和 Chrome 版本，以便避免未测试升级破坏工作台。
41. 作为试点维护者，我想在行情供应商选择前使用模拟数据完成 UI 验证，以便不假定未获许可的数据源可用。
42. 作为试点维护者，我想在两周试用后用明确场景评估价值，以便决定是否投资交易流水、文件导入、后台提醒或第二供应商。

## Implementation Decisions

- 一个私有 bundle 通过专用 DSH profile 组合。profile 移除标准根布局，挂载股票根布局，并保留原生会话列作为右侧 Agent。
- 股票根布局声明左导航、中间工作台、原生会话和按需详情展示所需的 slot；它不向标准根 slot 追加第二个注册，也不使用覆盖原生页面的 `shell.overlay` 作为主工作区。
- `PortfolioLedger` 是持仓事实的唯一 Module。它维护 `Account`、`Holding`、`CashBalance`、`WatchlistItem`、`ChangeRecord` 和 `RecycleRecord`，并提供账户和持仓的新增、修改、读取、软删除、恢复、备份与恢复能力。
- `PortfolioLedger` 把用户输入视为当前快照。它不从持仓变更推断真实买卖、已实现盈亏、税费或公司行动。
- `MarketData` 仅实现客户选定的一家供应商 Adapter。其 Interface 提供证券搜索、报价、日线、周线、基本事实、新闻或公告元数据、行业、汇率和市场状态；鉴权、限流、缓存、供应商字段映射和错误转换留在 Implementation 内。
- 未选定第二家正式供应商前，不建立公开多供应商 capability seam。出现第二个已获许可的 Adapter 后，才以 Service Definition、Service Provider 和 Consumer 三个角色建立该 seam。
- `RiskSummary` 从账本和行情构建资产、现金、CNY/HKD 换算、集中度、浮盈亏估算、行业映射、规则触发和新鲜度状态。汇率或价格过期时，它保留上次成功值并禁止用该值更新依赖实时价格的规则结果。
- `ContextComposer` 只根据用户当次勾选的范围创建 Agent 上下文草稿。草稿包含来源、截至时间、延迟或过期状态以及账户匿名标签；默认排除账户名和券商名。
- 发送后的草稿作为会话输入持久记录，以满足所有模型可见数据可从会话日志重建的 DSH 要求。插件不提供可让模型绕过用户选择读取账本的工具。
- Agent 指令和备忘录渲染固定使用“数据范围与时间、集中度、触发规则、待核验来源、反方情景”五段。遇到方向性证券建议请求时，返回拒绝和可用的事实材料。
- 账户、持仓、风险规则、供应商 Key 和本地变更使用当前 Windows 用户绑定的加密机制保存。Key 不在备份、诊断、更新或 UI 回显中出现。
- 备份使用用户密码加密。密码没有产品方恢复路径，导出前显示不可恢复提示。
- 插件使用 `dsh-web-app` 的 loopback 默认访问方式，不设置 LAN 地址或可信外部 Host。仅支持当前 Windows 用户的最新版 Edge 与 Chrome。
- 界面文案使用简体中文 locale dictionary。使用共享 UI primitives 和主题 token，但采用独立的图标、文案和视觉体系，不复制 dsh-trading 的代码、素材或近似界面。
- 试点更新由用户确认触发。更新前创建备份，失败时保留旧版本和数据；插件、DSH 和浏览器版本形成经过验证的组合。

## Testing Decisions

- 测试以用户可观察的结果为准，不断言私有 React 状态、内部缓存或 Module 的调用顺序。
- `PortfolioLedger` 通过其 Interface 验证：账户与持仓录入、跨账户聚合、手动变更记录、30 天回收、永久删除、加密备份/恢复和错误密码拒绝。
- `MarketData` 使用供应商 Adapter 的可控响应验证：代码搜索、字段规范化、延迟/过期状态、限流、失败、离页暂停和不把缓存旧价标为新价。
- `RiskSummary` 验证：CNY/HKD 折算、现金分母、相同代码聚合、A/H 分开、未分类行业、汇率过期和仅由用户规则触发的提醒。
- `ContextComposer` 验证：最小字段、账户匿名化、发送前预览、用户未发送时模型不可见、会话记录可重建已发送草稿，以及方向性建议的拒绝输出。
- 浏览器集成测试验证：专用 profile 的根布局、三栏可用、无数据引导、账户/持仓表单、详情与自选分离、市场数据故障状态、首次风险确认和 Agent 上下文预填。
- 录制的会话快照验证：风险备忘录的固定五段、来源和时间、缺数据时的待核验表达，以及买卖/目标价/仓位请求的拒绝。
- 更新与恢复测试验证：Key 不出现在备份或诊断导出、旧版本数据可恢复、失败更新不破坏现存数据。
- 测试结构遵循现有 DSH Web 的 host loopback、slot 注册、浏览器客户端和会话快照测试做法；每个新 model-visible 结果有对应的记录场景。

## Out of Scope

- 对接、抓取、自动登录、控制或嵌入同花顺。
- 对接中信证券、国兴、长江证券或其他券商；读取账户、订单、成交或对账单。
- CSV、Excel、PDF、文本或同花顺文件导入。
- 实盘或模拟下单、撤单、订单簿、盘口、交易策略执行或自动化交易。
- 逐笔交易流水、已实现盈亏、历史费用归因、自动公司行动处理和税务计算。
- 融资融券、期权、可转债、基金、债券、IPO、复杂衍生品、回测和自动选股。
- 多供应商切换、自动故障转移、后台轮询、系统通知、短信、微信、邮件、云同步、手机端和公网访问。
- 方向性投资建议、目标价、仓位建议、收益保证或投资顾问服务。
- 忘记备份密码后的恢复、产品方保存用户密钥或可识别持仓。
- 面向公众销售、公开下载或不经验证的 DSH 版本兼容性承诺。

## Further Notes

阶段 0 是唯一的外部前置条件。客户在实现真实行情前，必须选定并取得一家供应商的试用 Key 和书面确认：本地私有试点许可、A/港代码搜索、报价、日/周 K 线、行业、基本面、新闻或公告元数据、HKD/CNY 汇率、延迟、调用频率、价格和 Key 轮换方式。

已供考察但尚未选定的候选是同花顺 iFinD、东方财富 Choice 和 Tushare Pro。公开网页接口只能用于受控研究或模拟，不进入试点生产依赖。

试点在两周连续使用后完成验收：用户能在十分钟内创建至少两个账户和五条持仓；用户能识别市场、币种、行业或单标的集中度；用户能发送一个标的或全局摘要，并得到含来源、时间和不确定性且不含交易推荐的风险备忘录。

若试点通过，后续功能只根据客户实际证据排序。历史流水、文件导入、后台提醒或第二行情供应商均须单独成规格和任务，不回溯扩大本规格。
