# A 股与港股持仓工作台：私有试点方案

相关：[[../../research/2026-09-08-现有股票DSH插件功能调研]] · [[../../00-deepseek-harness索引]]

## 定位

为当前客户在 Windows 本机 DSH Web profile 中使用的本地持仓与风险辅助插件。它与同花顺并排使用，不读取、控制、抓取或嵌入同花顺，也不接入中信证券、国兴或长江证券。

软件不构成投资建议。Agent 只提供可追溯的事实、风险暴露、反方情景和待核验事项；拒绝买卖、持有、目标价、仓位和收益类建议。

## 首版冻结范围

| 纳入 | 不纳入 |
| --- | --- |
| 手动维护账户、现金和当前持仓快照 | 对账单或交易记录导入；读取券商、同花顺或实时账户 |
| A 股普通股、港股普通股、交易所 ETF；CNY 与 HKD | 融资融券、期权、可转债、基金、债券、IPO、回测与自动选股 |
| 资产、币种、行业和单标的集中度；估算浮盈亏 | 实盘或模拟下单、撤单、盘口和衍生品 |
| 价格摘要、日/周 K 线、少量指标、基本面、新闻与公告 | 自动交易流水、已实现盈亏与费用归因 |
| 用户设定的本地规则，打开工作台时显示触发状态 | 后台轮询、通知、短信、微信、邮件或云同步 |
| 加密备份/恢复、30 天最近删除、变更记录 | 忘记备份密码后的恢复机制 |

## 使用路径

1. 用户首次进入：创建账户卡片；选择 A 股或港股；从已配置的数据源搜索标的；填写数量、每股综合成本和可选的本币现金。
2. 用户查看首页：按账户或全局查看资产、现金、市场/币种/行业/标的集中度、浮盈亏估算、规则触发和数据更新时间。
3. 用户点选持仓或自选：查看价格、日/周 K 线、基础指标、基本面、新闻和公告。自选不计入资产或风险。
4. 用户点“发给 Agent”：先预填自己选择的最小上下文；审阅后点击发送。Agent 返回固定的持仓风险备忘录。

## 交互布局

左栏是分组的持仓与自选导航，显示市场、最新价、涨跌幅和小趋势图。中栏默认显示跨账户资产与风险总览；选择标的后切换为标的详情。右栏是可调整宽度的 DSH Agent 会话。底栏显示 A 股和港股交易时段与核心指数摘要。

布局借鉴 [[../../research/2026-09-08-现有股票DSH插件功能调研#已核实的实现|dsh-trading 的三栏工作流]]，但从零实现视觉、文案、图标和前端代码；不使用其 PolyForm Noncommercial 许可下的实现或素材。

## DSH 插件架构

```text
客户浏览器（仅 Edge / Chrome）
  └─ DSH Web Client
       └─ stock-workbench client module
            ├─ 左栏：持仓 / 自选
            ├─ 中栏：总览 / 标的详情
            └─ 右栏：Agent 上下文预填
                 │ 仅经用户审阅后发送
                 ▼
            当前 DSH 会话 / 已配置模型

本机 DSH Host（仅 127.0.0.1）
  └─ stock-workbench host module
       ├─ PortfolioLedger：持仓、现金、变更、最近删除和备份
       ├─ MarketData：唯一获准供应商的行情、K 线、资讯与基本面
       ├─ RiskSummary：估值、汇率、集中度、用户规则和过期状态
       └─ ContextComposer：最小模型上下文与投顾拒绝规则
```

插件以一个私有 DSH bundle 分发，在专用 profile 中叠加到 `dsh-web-app`。它只通过 Cordis 公开的 Web、工具、设置、凭证和会话扩展点工作；不增加新的 Node 启动入口，不修改 agent loop。

### Module 与 Interface

| Module | Interface | 隐藏在 Implementation 中的复杂性 |
| --- | --- | --- |
| `PortfolioLedger` | `listSummary`、`upsertAccount`、`upsertHolding`、`remove`、`backup`、`restore` | 当前 Windows 用户绑定加密、审计变更、30 天回收、备份验证、跨账户聚合。 |
| `MarketData` | `search`、`quote`、`series`、`instrumentFacts`、`marketStatus` | 供应商鉴权、请求节流、字段标准化、交易时段、缓存、延迟/过期标记和错误转换。 |
| `RiskSummary` | `portfolio`、`instrument` | CNY/HKD 估值、汇率日期、现金、行业映射、合并持仓、用户阈值和不使用旧价触发规则。 |
| `ContextComposer` | `draftPortfolioMemo`、`draftInstrumentMemo` | 用户勾选的最小字段、来源与时间、账户匿名化、发送前预览、拒绝投顾请求的提示语。 |

这些 Module 的 Interface 保持小而深：UI 和 Agent 不知道存储加密、数据源字段、汇率换算或规则计算的细节。真实行情供应商确定前不引入“多供应商”公开 seam；先实现一个获准供应商的 Adapter。第二个正式 Adapter 出现时，才将 `MarketData` 的内部 seam 提升为公开 capability seam。

## 本地数据与安全

- 仅监听 `127.0.0.1`；不允许局域网或公网访问。
- 本地持仓、账户、规则和数据源 Key 由当前 Windows 用户绑定的加密机制保护；Key 不进入备份、更新包、导出或日志。
- 备份以用户自设密码加密；忘记密码不可恢复，导出时明确告知。
- 删除对象进入最近删除 30 天，用户可恢复或立即清空；永久删除后移除其变更记录。
- 无单独工作台密码，依赖本机 Windows 用户会话与 localhost 限制。
- 数据发往模型前由用户逐次审阅和点击发送；默认不含账户名、券商名和完整全局持仓。
- 诊断日志只保留版本、状态码、耗时、错误码和数据时间；报障日志由用户手动导出并脱敏。

## 行情供应商准入门槛

客户已选定独立实现的东方财富公开 JSON 作为当前唯一 Adapter。该来源无用户 API Key、无 SLA，条款风险由私有试点接受。未选定前只能用模拟数据开发 UI；当前 Adapter 已解除票据 05 的阶段 0 阻塞。第二家付费供应商仍须满足下列门槛。

1. 书面条款允许本地、私有试点使用。当前公开 JSON 仅用于本次私有试点，不作为第二供应商或公开发布依赖。
2. 覆盖 A 股与港股的代码搜索、最新价、日 K、周 K、行业分类、基本面、新闻或公告元数据，以及 HKD/CNY 汇率；每项必须确认延迟和权限。
3. 有稳定的程序化接口、明确的调用频率、凭证轮换方式和可测试环境。
4. 能在客户预算内使用，且不会要求把客户持仓传回供应商。
5. 在 Windows + localhost 的 DSH 插件中可安全保存并轮换 Key。

## Agent 风险备忘录

默认固定为五段：

1. 数据范围、来源、延迟/过期状态和截至时间。
2. 市场、币种、行业、单标的及现金的集中度。
3. 用户已设置且已触发的规则及事实依据。
4. 当前标的的新闻、公告和待核验事项，附原始来源。
5. 反方情景与用户需要自行判断的问题。

请求买卖、目标价、仓位、收益或确定性判断时，Agent 拒绝提供，并仍可返回上列事实和风险材料。证券投顾与荐股软件的监管问题需要在商业化前由有资格的中国证券法律顾问复核。

## 分阶段交付

| 阶段 | 交付物 | 完成条件 |
| --- | --- | --- |
| 0. 数据源决策 | 供应商对照、选定东方财富公开 JSON、独立实现单一 Adapter | 搜索/报价/日周 K/行业/新闻或公告元数据/HKDCNH 可测；无用户 Key；不接第二家供应商。 |
| 1. 本地账本 | 账户、现金、手动持仓、验证、加密存储、变更、最近删除、备份/恢复 | 单机断网仍能维护持仓；错误密码不能恢复备份；删除可在 30 天内恢复。 |
| 2. 工作台 | 三栏布局、总览、自选与标的详情；来源/时间/过期状态 | 无持仓、缺数据、延迟行情和 API 故障均有清楚状态。 |
| 3. 数据与风险 | 单供应商 Adapter、汇率、估值、集中度、用户规则 | 不把旧价当新价；未分类行业和汇率过期均可见；自选不计入资产。 |
| 4. Agent 受控上下文 | 预填预览、最小范围发送、风险备忘录、投顾拒绝 | Agent 无法主动读取全账户；输出每个事实都有来源和时间。 |
| 5. 私有试点 | 固定版本安装包、更新/回滚、脱敏诊断、客户验收 | 客户在两周试用中完成下列验收。 |

## 试点验收

1. 用户能在十分钟内创建至少两个账户和五条持仓。
2. 用户能在总览识别市场、币种、行业或单标的集中度。
3. 用户能发送一个标的或全局摘要，得到带来源、时间和不确定性说明的风险备忘录，且没有买卖推荐。

通过后再按客户的真实使用证据排优先级：历史流水、文件导入、后台提醒或第二数据供应商；任何扩展都不自动进入首版。
