## Review

- **Blocker：新增 `hot.render()` 在 Handsontable 15.2 的实际加载时序中是冗余请求，未改变最终重绘行为，因而没有证据表明它能修复首行折叠节点问题。**  
  位置：`src/components/report/preview/plugins/treeRender/utils.ts:307-311`。  
  调用链中，`handleLoadGlobalSettings` 先在 `src/components/report/preview/tableSheets/utils.ts:184` 调用 `suspendRender()`，随后三次 `updateSettings()`，在 `:214` 初始化树元数据，最终在 `:217` 调用 `resumeRender()`。Handsontable 15.2 的实现显示：
  - `node_modules/handsontable/core.js:1791-1800`：`resumeRender()` 在解除最后一层挂起时**无条件执行一次渲染**；
  - `node_modules/handsontable/core.js:1813-1820`：挂起期间调用 `render()` 只设置 `renderCall=true`、`forceFullRender=true`，不会立即绘制；
  - `node_modules/handsontable/tableView.js:163-174`：挂起期间 `view.render()` 不执行 draw，也不会创建注释所称的“earlier row-0 render”。
  
  使用仓库实际 Handsontable `15.2.0` 和与 `handleLoadGlobalSettings` 相同的 suspend/update/load/meta/resume 顺序进行 jsdom 验证：调用新增 `hot.render()` 前，`renderCall` 和 `forceFullRender` 已经都是 `true`；有无该调用，恢复时均只从 3 次受挂起保护的 `view.render` 尝试变为 4 次、即均只发生一次最终 draw。换言之，新增调用既没有增加第二次首屏绘制，也没有改变 full-render 标志。当前修改应继续定位真实根因，或用真实 renderer/DOM 证明该调用确实改变首行结果，否则不能认为缺陷已修复。
