# ADR-0004：第一阶段复用现有服务适配层

第一阶段前端对接直接复用 `udp-report-table` 和 `PrintPlugin` 当前基于 `NG.request` / `core.request` 的服务适配层，暂不引入由宿主注入 API 的新抽象。这样可以把本阶段范围限定在组件能力、参数/类型整理、错误处理和真实接口联调，避免把后端未完成或宿主架构改造混入前端交付。

相关：[[report-table-同步术语表]] · [[research/2026-08-18-硕正报表第一阶段对接范围]] · [[00-版本总览]]

## Considered Options

- 直接复用现有服务适配层：本阶段采用，改动小，能立即验证现有 `/reportcenter/*`、`/RW/Print/*` 契约。
- 改为宿主注入 API：暂不采用，适合后续多宿主或服务地址差异明确后再评估。

## Consequences

- 第一阶段前端仍依赖现有请求运行时和接口路径，需在联调清单中锁定鉴权、错误码和响应结构。
- 后续如需解耦宿主或替换服务端，需另立架构改造，不将本阶段的直接复用误认为长期边界。
