# BUG-20260807-001: nova 审批附件计数重开归零

相关：[[00-版本总览]]

## 现象

在审批详情页上传附件后，关闭底部审批意见弹窗并重新打开，附件按钮右上角的数量显示为 `0`。

## 已确认根因

`OpinionPopUp` 在收起和展开之间切换 `minSize` 的两个渲染分支，导致其中的 `AttachmentHelp` 卸载并重新挂载。`AttachmentHelp` 的 `fileList` 初始值固定为空数组，传入的 `value.label` 只在 `useUpdateEffect` 中同步；该 Hook 明确跳过首次挂载。因此重开时虽传入了已有附件名，组件内部列表仍为空，`Upload` 传给徽标的 `attLength` 也随之为 `0`。

## 关联风险

`OpinionPopUp` 向父组件回传的字段名是 `attachmentList`，详情页却读取 `target.attachList`。当前收起/展开流程依赖 `OpinionPopUp` 自身状态，所以只表现为计数错误；若该组件被真正卸载，父层也无法正确恢复附件列表。

## 修复

- `AttachmentHelp` 首次挂载时直接以 `value.label` 初始化 `fileList`，使重新打开审批意见弹窗后徽标立即恢复已有附件数量。
- 保留原有 `useUpdateEffect`，继续处理已挂载组件后续收到的新附件值。

## 验证

- 新增回归用例：已有两个附件时卸载并重新挂载，附件数量仍为 `2`。
- `npm run build` 已通过。
- 当前依赖树缺少 `ts-node` 与 `ts-jest`，无法执行项目的 Jest 用例；独立 `tsc --noEmit` 同样被 `@types/node/stream.d.ts` 的既有语法错误阻断。
