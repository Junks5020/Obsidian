# ng-design 附件术语表

记录 `ng-design` 附件组件共享的业务语言与权限概念。

相关：[[00-版本总览]] · [[ng-design-ADR-0001-附件权限分类块透传]]

## Language

**现代附件**：由 React 现代附件组件渲染的附件区域，包括表格附件、表单附件、标签附件和图片附件模式；不包含旧版 `openOldAttachment` 弹窗。

**附件分类**：现代附件按业务来源划分的五个类别——单据附件、审批前附件、审批后附件、来源单据附件、工作流附件。审批前附件是单据附件在单据已审批后的只读呈现，二者共用同一份权限；独立工作流附件弹窗与工作流附件 tab 同属工作流附件分类。

**权限分类上下文**：一次附件操作进行权限判断时采用的完整业务上下文，至少明确附件分类，并在适用时包含当前类型选择及依赖前端状态的判断条件。同一次操作从界面呈现到最终执行必须使用同一份上下文快照。它独立于 UI tab 的具体形态；独立工作流弹窗即使没有工作流 tab，也必须使用工作流附件权限分类。

**附件分类标识**：现代附件只接受 `attach`、`pendingApprovedAttach`、`approvedAttach`、`oriBizAttach`、`workFlowAttach` 五个分类值，并通过共享的 `AttachmentCategory` 类型表达。旧公开 handler 完全缺少分类上下文时默认 `attach`；显式传入非法值时 fail-closed，不能静默回退到单据权限。

**分类权限块**：附件初始化接口按附件分类分别返回的权限对象：单据附件（`billAttachButtonRights`）、审批后附件（`approvedAttachButtonRights`）、来源单据附件（`sourceAttachButtonRights`）、工作流附件（`workflowAttachButtonRights`）。是现代附件操作可见性与可用性的唯一业务来源。

**按类型控制**：初始化接口的 `controlByType` 开关；仅作用于单据附件、审批前附件和审批后附件。为真时前两者取 `billAttachTypeButtonRights[typeId]`，审批后取 `approvedAttachTypeButtonRights[typeId]`；来源单据附件与工作流附件始终取各自普通分类权限块，不使用 `typeId`。

**目标类型约束**：单据附件、审批前附件和审批后附件在存在分类树时，新增或导入附件必须先选中具体类型。未选类型只会令 `canAddToSelectedType` / `canImportToSelectedType` 为假，并由 UI 与 handler 共同拒绝；它不改写分类权限块的 `add` / `imp` 原值。来源单据附件与工作流附件不受该约束影响。

**全部类型聚合态**：按类型控制时未选中具体 `typeId` 的浏览状态。它不合成虚构的聚合权限；单条操作按记录所属类型判权，多选操作要求全部记录均获授权，类型块缺失或记录缺少 `typeId` 时操作 fail-closed。聚合态不提供新增或导入；只要处于按类型控制，打包下载在聚合态和具体类型态都不提供。

**权限数值语义**：权限块内除 `visible` 外各按钮取值的统一含义——0 置灰禁用、1 可用、2 隐藏；由后端按用户权限返回，前端原样透传，不做覆盖。

**统一按钮权限**：`unifyButtonRights`（及按类型形式 `typeButtonRights`），后端为兼容旧版本前端而保留的冗余字段；新版现代附件不读取。

**前端权限覆盖参数**：`btn`、`permission`、`downloadAttachment` 及 URL `btn*` 参数等曾用于直接改写现代附件按钮权限的兼容入口。新版现代附件保留其公开声明但不读取，不能放宽或收紧分类权限块返回的授权。

**本地交互锁**：`disabled=true` 对当前附件组件实例施加的本地只读约束，只收紧新增、导入、删除、编辑、分类编辑、归档、拖拽和保存等变更操作；不改写分类权限块原值，也不影响由后端权限控制的查看、预览和下载。`status` 是初始化请求和弹窗生命周期参数，`status='view'` 不自动产生本地交互锁。

**附件可见性**：权限块中的 `visible` 字段，当前只定义 0/1，表示附件是否可见。本轮保留该字段及类型声明但暂不消费，不用它控制 tab、toolbar、列表、内容区或任何操作，也不把它纳入按钮权限的 0/1/2 呈现规则。

**按类型打包约束**：当前打包接口只按整个附件 session 创建 ZIP，不能携带 `typeId`，因此 `controlByType=true` 时无论是否选中具体类型，都隐藏打包下载入口并由 handler 拒绝调用。普通单文件下载仍按记录所属类型的 `download` 判权。

**附件编辑权限**：后端 `edit` 对所有修改已有附件或其元数据的操作提供统一授权，包括控件编辑、修改备注、拖拽排序、归档切换、标签编辑和编辑分类。前端内部的 `editCategory` 只是逐值继承 `edit` 的呈现别名，不是新的权限字段；UI 与 handler 必须使用同一授权结果，本地交互锁可额外收紧。

**权限初始化状态**：现代附件初始化权限时的显式三态。`pending` 表示结果未知，必须撤销上一轮权限和内容；`ready` 表示接口成功，分类块是否存在由 fail-closed 规则另行处理；`failed` 表示网络异常、接口失败或响应不可解析，整个现代附件区域不渲染。分类块缺失不属于初始化失败。

**本地新增附件**：通过文件选择、拖拽、粘贴、图片选择或移动端上传把本地文件加入当前附件区域的操作，由当前分类权限块中的 `add` 控制其入口和最终上传执行。它不包含共享导入，也不直接授权整会话提交或决定必填附件校验。

**附件会话提交**：`handleSave` 将当前附件 session 中经授权产生的待提交变更保存到业务单据。它不是新的按钮权限，也不直接复用 `add`、`imp`、`edit` 或 `delete` 中任一字段；`disabled=true` 时拒绝，有待提交变更时请求保存，无变更时不请求接口并按成功返回。

**附件完整性校验**：`handleValid` 在显式确认或保存前，按操作完成后的最终附件集合检查必填分类，不读取任何按钮权限。缺少必填附件或权限初始化失败时拒绝确认；取消或直接关闭不执行校验。

**附件查看权限**：后端 `view` 统一授权所有读取附件内容的路径，包括文件名预览、控件预览或在线查看、图片缩略图和大图预览，以及 `customOpenTab`。前端 `preview` 只是逐值继承 `view` 的别名；`view=0` 保留记录但禁用查看，`view=2` 隐藏查看入口，两者都不请求任何预览资源。

**附件下载权限**：后端 `download` 统一授权单文件下载、批量所选文件下载、预览页内下载，以及非按类型控制场景的 ZIP 下载。前端 `zipDownload` 只是逐值继承 `download` 的别名，并受按类型打包约束进一步收紧；`download=0/2` 时不请求下载信息、不写下载日志，也不执行下载前业务校验。

**下载记录查看**：查看附件被谁在何时下载的只读审计信息，由 `view` 控制而不读取 `download`。`view=0` 时入口禁用，`view=2` 时隐藏，两者都不请求下载记录接口。

**撤销会话新增**：移除本组件会话中经 `add` 或 `imp` 授权后新引入且尚未提交的附件。前端必须记录其本会话来源，`asrFlag=0` 只校验未提交状态，不能单独作为来源依据；选择中全部记录同时满足这两个条件时才允许撤销。它不等同于删除既有附件，不改写 `delete` 原值，且受本地交互锁收紧。

**既有附件删除**：删除已存在或已提交附件的操作，由记录所属分类及类型的 `delete` 控制。多选要求全部记录均为 1；0 置灰、2 隐藏，handler 同样拒绝非 1，且受本地交互锁和标签附件审批保护进一步收紧。它不包含撤销会话新增。

**标签附件删除保护**：标签附件删除已通过当前分类 `delete=1` 授权后执行的单条记录约束。单据未审批时允许删除；单据已审批时仅允许删除记录自身标记为审批后的附件。它只收紧后端授权，不会把 0/2 提升为可用。

**共享导入**：将历史附件或他人共享的附件复制到当前附件区域的操作，由当前分类权限块中的 `imp` 控制，覆盖工具栏入口、导入弹窗和最终复制 handler；它不等同于本地上传，也不授权修改当前附件的共享配置。

**附件共享配置**：当前附件的“共享方式/共享给”元数据。只读展示不要求操作权限；修改属于已有附件元数据编辑，由 `edit` 控制，不读取 `imp`。

**下载前业务校验**：后端分类权限允许下载后，由业务方在实际下载或打包下载前执行的附加校验。它只能取消本次操作，不能授予后端已拒绝的下载权限，也不是附件权限来源。
