# 01 — 权限核心与纯函数测试

Parent: [[work-items/attachment-category-rights/spec]]

**What to build:** 建立唯一的分类权限解析和纯逻辑判定层，让每个组件都能得到同一份、可测试的权限上下文与操作结果。

**Blocked by:** None — frontier

## Scope

- 用共享 AttachmentCategory 和现有 AttachmentPermissionContext 表达 attach、pendingApprovedAttach、approvedAttach、oriBizAttach、workFlowAttach；上下文至少包含 attachType、isWorkFlow、controlByType、typeId、分类树状态和会话 provenance；isWorkFlow=true 始终选择 workFlowAttach；无分类的旧公开调用默认 attach，显式非法分类 fail-closed 并在开发环境告警。
- 实现普通块和按类型块的映射：前三类在 controlByType=true 时按 typeId 取 billAttachTypeButtonRights 或 approvedAttachTypeButtonRights；来源和工作流永不按类型。
- 完全移除 unifyButtonRights、typeButtonRights 和前端兼容回退；分类块或类型块缺失时返回 ready 下的 fail-closed 结果，记录元数据仍可展示，受控操作按 0。
- 所有按钮值 0/1/2 原样透传。editCategory 继承 edit，preview 继承 view，zipDownload 继承 download；controlByType=true 时 ZIP 额外强制隐藏和拒绝，不能被 download=1 重新打开。
- visible 只保留 0|1 类型和数据字段，本轮不参与解析结果、渲染、请求或授权。
- 只保留三类独立状态推导：canAddToSelectedType/canImportToSelectedType、canDeleteTemporaryAttachments、canDeleteApprovedAttachment。不得恢复审批保护、审批前禁 add、工作流/来源置 2 或把 delete 提升为 1；归档能力不得另造前端权限覆盖。
- 提供单条、全类型聚合、多选 2 > 0 > 1 聚合及逐记录复核的纯函数；缺 typeId 的按类型记录按 0。

## Checklist

- [x] 定义分类、按钮键、权限块和解析结果的精确类型。
- [x] 让 UI 可区分可用、置灰、隐藏和 fail-closed，且 handler 使用同一结果。
- [x] 将本会话 add/imp 来源记录与 asrFlag=0 检查建模为临时撤销能力，不改写 delete；纯函数必须拒绝只有外部 asrFlag=0 而没有当前会话 provenance 的记录。
- [x] 将 Label 单条审批后删除保护建模为 canDeleteApprovedAttachment 的额外收紧条件。
- [x] 为下载、下载记录、onBeforeDownLoad、disabled 和 handleSave/handleValid 提供不含 UI 副作用的 evaluator；它们不是新的权限覆盖来源，归档只与后端 allowAttachArchive 和 edit 组合。
- [x] 重写现有 regression 测试中把临时 delete 提升为 1 的旧断言。

## Acceptance

- 五分类普通块、前三类 per-type 块、工作流优先级、默认分类、非法分类和缺块行为均有测试。
- 同时返回兼容字段和分类字段时只取分类字段；0/1/2 与 visible=0/1 的语义断言明确区分。
- 未选类型只影响新增/导入，delete 原值保持；controlByType 下 ZIP 在全部类型和具体类型均为隐藏/拒绝。
- 临时附件在本会话 provenance=add/imp、asrFlag=0、add=1 且 delete=0 时可撤销；外部仅 asrFlag=0 不可撤销，既有附件仍受 delete；混合选择不部分执行。
- npx tsx 纯逻辑测试可重复通过，且不依赖 React 或浏览器。
