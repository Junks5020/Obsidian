# 报表图片双击预览

相关：[[report-web-术语表]] · [[00-版本总览]]

## 目标

为桌面端报表提供统一的图片双击预览。用户在设计器或任一 `PreviewTable` 调用页面双击图片单元格或浮动图片时，在所属报表实例内打开预览层，可放大、缩小、重置与 90° 旋转。

## 范围与交互契约

- 目标对象仅为 `cellType: image` 的 [[report-web-术语表#图片单元格|图片单元格]] 与 [[report-web-术语表#浮动图片|浮动图片]]。
- 设计器和所有桌面端 `PreviewTable` 调用页面（报表、流程、图表、数据集、打印预览）使用相同交互；移动端不作本轮改造。
- 预览层提供放大、缩小、重置、90° 旋转与关闭；点击遮罩或按 `Esc` 关闭。不提供下载、翻转、多图切换或其他编辑工具。
- 图片没有有效地址、尚未成功加载或加载失败时，不打开预览；仅提示“图片暂不可预览”，且不因此重复请求图片资源。
- 浮动图片与图片单元格重叠时，视觉上最上层且实际接收双击的图片独占处理事件，不向底层透传。
- 合并图片单元格的任一可见区域均打开合并区域左上角锚定的图片。
- 设计器中的浮动图片双击不再打开管理抽屉；浮动图片管理继续由既有工具栏入口打开。

## 非目标

- 工作表背景图、图表内图片、上传控件缩略图、打印/导出产物以及其他非 `cellType: image` 资源。
- 移动端单击、长按或双击替代手势。
- 下载、翻转（水平/垂直）、多图上一张/下一张，以及缩放/旋转/重置以外的编辑工具。
- 改动 schema、后端接口、保存数据、打印、PDF 或 Word 导出逻辑。

## 实现约束

- 预览层必须归属于触发它的报表实例，不能把 UI 直接裸挂到 `body`；复用现有实例 overlay 约束。
- 渲染层保持裸 `<img>` 不变；预览弹层复用 antd 受控 `Image`，经 `getContainer` 落到实例 scope、`toolbarRender` 裁到放大/缩小/重置/旋转/关闭、`destroyOnHidden` 关闭即销毁。
- 使用当前已渲染图片的已认证地址；不新建资源下载或字段解析链路。
- 图片单元格在设计器已有 `editor: false`；预览触发不得引入编辑状态或破坏普通单击选中。
- 关闭预览后恢复焦点，不遗留事件监听器、portal 或图层节点。

## 验收

- [ ] 设计器中的普通与合并图片单元格可双击预览，且不会开始单元格编辑。
- [ ] 设计器中的浮动图片可双击预览；工具栏仍可打开图片管理抽屉。
- [ ] 全部桌面端 `PreviewTable` 调用页面中的两类图片均可双击预览。
- [ ] 模态层保持实例归属，支持放大/缩小/重置/旋转、遮罩与 `Esc` 关闭。
- [ ] 无效、未完成加载或加载失败的图片不会打开模态层，也不产生额外请求。
- [ ] 重叠与合并单元格场景符合本规格的命中规则。
- [ ] 现有浮动图片、预览表格及构建/类型检查回归通过。
