# ADR-0003：字体清单由前端维护并从静态资源目录加载

后端提供的 `NG3Resource/reportcenter/fonts` 是可直接拼接文件名访问的静态字体资源目录，不是返回字体元数据的查询接口。我们决定由前端维护固定的报表字体清单，并从 `/NG3Resource/reportcenter/fonts/{文件名}` 加载对应字体文件；不为此增加字体列表请求。这样可以保持字体选项、标准名称和字重映射的版本化契约，同时避免运行时列表变化导致已保存报表无法稳定解释。

## Consequences

- 后端新增、删除或重命名字体文件时，前端清单必须配套发布。
- 部署环境必须保持 `/NG3Resource/reportcenter/fonts/{文件名}` 可访问，并允许浏览器字体加载所需的来源策略。
- 字体下拉框按字体族展示 10 个选项；`SourceHanSansSC-Bold.otf` 与 `Carlito-Bold.ttf` 是对应字体族的粗体字重资源，不作为独立选项。
- 字体族是否具备真实粗体资源由清单显式描述；粗体交互继续使用设计器现有的独立加粗命令。
- 字体清单明确区分三类名称：中文名称用于界面展示，标准名称写入 `cell.fontFamily`，文件名仅用于拼接静态资源 URL。
- 前端内部 ID 不进入保存契约或用户可见文案；文件名和中文名称也不得替代字体标准名称落库。
- 新字体列表中的宋体选项为“思源宋体-标准常规”，保存 `Source Han Serif SC Regular`，加载 `SourceHanSerifSC-Regular.otf`。
- 旧 `SongTi` 不进入新报表的字体选项；只有读取存量报表时才作为兼容值识别。
- 字体资源按需加载：打开报表时加载已引用的字体及字重，用户选择字体或启用粗体时加载新增资源；打开下拉框不预取全部文件。
- 相同字体文件 URL 在页面生命周期内只加载一次，避免重复请求和重复注册 `FontFace`。
- 字体资源加载失败只影响当前浏览器显示：每个失败字体在一次页面会话中提示一次并使用 CSS fallback，不得改写 `cell.fontFamily` 或用户选择。
- 服务端打印/导出继续按已保存的字体标准名称处理；页面重新打开后允许再次请求此前加载失败的字体。
- 报表设计、报表预览、打印设计表体、打印预览以及打印页眉页脚共用同一份 10 字体清单和标准名称映射，不建立模式专属字体名单。
- 所有字体族均保留加粗能力：思源黑体与 Carlito 使用真实 Bold 文件，其余字体由浏览器和打印引擎合成粗体；不得因清单缺少 Bold 文件禁用加粗命令。
- 所有字体族均保留斜体能力，由浏览器和打印引擎合成斜体；斜体只通过既有样式 class 表达，不修改 `fontFamily`，也不请求不存在的 Italic 文件。
- 字体文件内容以文件名为不可变标识；资源内容升级必须使用新文件名并配套更新前端清单，不允许同名替换。
- 前端依赖正常的浏览器/CDN 缓存，不给字体 URL 添加随机时间戳或逐次请求的缓存绕过参数。
- 本期字体清单是由思源黑体、思源宋体、朱雀仿宋、霞鹜新致宋、汇文仿宋、汇文正楷、Arimo、Caladea、Carlito、Tinos 组成的封闭集合，不加入系统字体或旧 `SongTi`。
- 后续新增受支持字体必须更改版本化前端清单并随前端发布；运行时未知字体仍按兼容规则保留，但不自动升级为受支持选项。
