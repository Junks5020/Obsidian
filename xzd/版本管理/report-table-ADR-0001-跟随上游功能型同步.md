# ADR-0001：跟随上游（6.5.2-dev）做功能型同步，包括跟随移除

相关：[[report-table-同步术语表]] · [[report-table-6.5.2-7.0-功能同步计划]]

udp-report-table 是 report-web 报表组件的 7.0 抽离包。我们决定：**以 report-web `6.5.2-dev` 为上游做单向功能型同步——上游的新增、修复、移除都跟随**，按功能血缘判断跟随范围（血缘在上游的功能即使被 7.0 小幅扩展过也跟随；7.0 原生功能不参与同步）。理由：同步的意义就是让 7.0 与 6.5.2 能力对齐；若因"本地改过"而滞留上游已召回的功能，同步规则即失效，且 7.0 会携带上游已判定有问题的代码首发。

## Consequences

- 首次应用（2026-08-05，ng-design `14bfbf811`）：跟随上游 `c6210ffc`（当时仅本地提交、未推送 origin）移除预览表格休眠接线、预览右键「隐藏当前行/列」、预览态强制分页行头标记；其中预览行列隐藏在 7.0 曾被增强（列压缩至 20px、支持列隐藏），一并撤除。同时移植该提交新增的「单元格内容溢出时 title 悬浮显示」。
- 唯一有意偏离：7.0 抽离期已有的卸载 `destroy` 清理保留（上游移除时连带丢失，组件包反复挂载/卸载会泄漏）。
- 上游移除时未清理的残余（store 字段、prop 声明等）在 7.0 侧按"同步"口径保持一致，不做额外清理也不保留死代码接线。
- 上游是移动目标（曾发生 rebase 与本地未推送提交）：每次同步任务以 `origin/6.5.2-dev` 为基准核对，本地未推送提交单独确认后再跟随。
