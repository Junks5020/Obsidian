# nova 钉钉文件预览替代方案

相关：[[00-版本总览]]、[[ng-design-附件术语表]]

## 结论

对于只保存在 `JFileSrv` 的文件，当前公开能力中没有“把任意 Office/PDF URL 直接交给钉钉在线 WPS 内核”的 JSAPI。

最接近“点击即预览且不弹保存目录”的方案是：

1. `dd.downloadFile({ url, header })` 将文件下载到钉钉管理的临时路径。
2. 使用返回的 `filePath` 调用 `dd.openDocument({ filePath, fileType })`。

它不需要钉盘 `spaceId/fileId` 和文件授权，也不会让用户选择钉盘目录；但仍会产生客户端临时缓存，并非纯在线零下载预览。若要求使用钉钉在线文档/WPS 内核且不产生客户端临时文件，文件仍需先进入钉钉存储。

## 能力对比

| 方案 | 自有 URL | 进钉盘 | 临时下载 | 适用范围 |
| --- | --- | --- | --- | --- |
| `downloadFile + openDocument` | 是 | 否 | 是 | 文档/PDF/ZIP |
| `previewImage` | 是 | 否 | 客户端管理 | 图片 |
| `previewMedia` | 是 | 否 | 客户端管理 | 图片/视频，移动端为主 |
| `previewFileInDingTalk` | 否，只接收钉盘 ID | 是 | 否 | 钉盘在线预览 |
| 服务端 `openInfos/query` | 否，只支持钉盘 dentry | 是 | 否 | PC/H5 钉盘预览 |
| H5 自有预览页 | 是 | 否 | 浏览器加载 | PDF/媒体/转码后的 Office |

## 临时下载后打开文档

`downloadFile` 输入远程 `url`，可选传 HTTP `header`，返回“文件临时存放位置” `filePath`。官方网页应用版本要求为 Android/iOS/Mac/Windows 7.0.10、Harmony 7.0.0，全端均标注支持且无需 JSAPI 鉴权。

来源：[downloadFile 官方文档](https://open.dingtalk.com/document/orgapp/jsapi-download-file)

`openDocument` 仅接受本地 `filePath`，不能直接传远程 URL。支持 `doc/docx/xls/xlsx/ppt/pptx/pdf/zip`；由于临时路径不一定保留扩展名，应显式传 `fileType`。网页应用版本要求同样为 Android/iOS/Mac/Windows 7.0.10、Harmony 7.0.0。Android 明确仅支持在钉钉内打开 PDF，其他格式不支持端内访问。

来源：[openDocument 官方文档](https://open.dingtalk.com/document/orgapp/jsapi-open-document)

```ts
const { filePath } = await dd.downloadFile({
  url: signedPreviewUrl,
  header: requestHeaders,
});

await dd.openDocument({
  filePath,
  fileType,
});
```

Android 上的 Word/Excel/PPT 应优先由现有 `JFileSrv` 预览服务转换为 PDF，再执行上述链路。

## 按媒体类型直接预览

图片可直接调用 `dd.previewImage({ urls, current })`。官方支持 H5/小程序的 Android、iOS、Harmony、Mac、Windows，无需钉盘。

来源：[previewImage 官方文档](https://open.dingtalk.com/document/orgapp/jsapi-preview-image)

已安装的 `dingtalk-jsapi 3.2.8` 还暴露了 `previewMedia({ sources })`，类型声明用于远程图片和视频；SDK 能力映射标注 Android/iOS 7.1.21、Harmony 7.0.0，未标注 PC，采用前需真机验证。

来源：`mobile-web/node_modules/dingtalk-jsapi/api/union/previewMedia.d.ts`、`previewMedia.js`

## 钉盘在线预览

`dd.previewFileInDingTalk` 只接受 `corpId/spaceId/fileId/fileName/fileSize/fileType`，不能传外部 URL。预览前需要文件 ACL 授权。现代文档支持 Android 6.0、iOS 6.0、Harmony 7.0，不支持 Mac/Windows。

来源：[previewFileInDingTalk 官方文档](https://open.dingtalk.com/document/orgapp/jsapi-preview-file-in-ding-talk)

PC 端服务端接口为：

`POST /v1.0/storage/spaces/{spaceId}/dentries/{dentryId}/openInfos/query?unionId=...`

它同样只适用于钉钉存储文件，不是任意外部 URL 的转换接口。

来源：[获取文件预览或编辑信息](https://open.dingtalk.com/document/development/obtains-the-object-preview-or-editing-information)

## 授权边界

- 新版普通“添加权限”接口要求 `dentryUuid`、操作者 `unionId` 和成员/角色信息，当前文档只标明支持企业内部应用。
- 官方 OA 审批附件授权使用钉钉 `userId + processInstanceId + fileId`，支持企业内部应用和第三方企业应用，而且每次预览前都要授权。
- nova 的 `appFlow` 是自有工作流，不能因业务名称是“审批”就使用钉钉官方 OA 附件授权。

来源：[添加权限](https://open.dingtalk.com/document/development/add-permissions-file)、[授权预览审批附件](https://open.dingtalk.com/document/development/official-authorized-preview-approval-attachment)

## 文档和 SDK 差异

- 旧版 H5 `biz.cspace.preview` 文档曾标注 PC 支持，现代 `previewFileInDingTalk` 文档和 SDK 统一映射未声明 PC 支持。
- 官方 `downloadFile` 网页标注 PC 7.0.10；本地 SDK 的统一 `downloadFile` 映射未列 PC，但 `biz.file.downloadFile` 映射列出 PC 7.0.15。

因此 PC 必须做目标客户端版本 PoC，不能只依据旧文档。

## nova 推荐顺序

1. 先用 PDF 验证 `dd.downloadFile -> dd.openDocument`，覆盖 Android、iOS、Windows，确认不弹保存路径。
2. Android 的 Word/Excel/PPT 使用现有服务端 PDF 转码结果；iOS/PC 再验证原格式。
3. 图片继续使用 `previewImage`；视频单独验证 `previewMedia`。
4. 不支持或失败时回退到现有 H5 预览组件，不回退到会触发下载提示的 `openLink`。
5. 使用短效签名 URL 或 `downloadFile.header` 鉴权，避免在 URL 中暴露长期 access token。

该方案只需调整钉钉适配器和预览参数，不要求建设钉盘空间、文件同步和授权链路。
