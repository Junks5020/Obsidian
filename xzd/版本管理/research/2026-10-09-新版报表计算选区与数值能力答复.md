# 新版报表：计算、选区与数值能力答复

相关：[[00-版本总览]] · [[report-table-同步术语表]] · [[report-table-ADR-0011-报表设计流程宿主执行器接管]] · [[report-table-ADR-0008-第一阶段不实现公式引擎]]

本文根据组件库当前分支的源码、公开类型和示例整理。已确认前端计算接管、结果展示和公式保留能力；服务端计算范围、财税参数及实际计算结果仍需后端联调确认。

| 问题 | 当前确认的能力 | 仍需确认或补齐的部分 |
| --- | --- | --- |
| 计算接口与范围 | 有 `previewReportData` 执行器；提交当前未保存的完整设计；展示多表计算结果；关闭计算后恢复原设计和公式 | 现有后端是否计算全部工作表、是否支持范围计算；组件没有统一的范围计算 API |
| 获取选中区域 | 可选择区域；内部选区事件包含起止坐标 | 设计器公开 `reportApi` 没有完整范围读取方法；内部事件接法尚未形成稳定的公共契约 |
| 数值与格式 | API 可以写入数字；预览可分离原始数字与格式化显示值；字段和普通表达式格有格式规则配置 | 默认手工输入仍为文本；财税面板没有格式配置；完整数值类型、负数格式及保存加载闭环需要补齐 |

## 1. 计算接口怎么接入，计算结果如何显示，公式如何保留？

### 1.1 已有入口与实际地址

`DesignReportTable` 提供 `apiExecutor.previewReportData`，用于接管计算预览请求。未提供执行器时，组件使用内置请求地址：

```text
/reportcenter/reportDesign/previewReportData
```

这是组件源码登记的实际地址。本文没有另外假设“全部计算”接口，也不将前端能够提交完整设计解释为后端已经支持全部工作表计算。

开启 `financeTax` 后，顶部显示“计算”按钮。用户点击后，组件收集当前未保存的设计并调用计算入口。执行器负责请求发送、业务参数补充与响应适配，组件负责 loading、成功判断、结果展示和计算态切换。

以下示例复用现有平台地址，演示执行器的接法；是否接收新增财税参数、计算哪些工作表，需要按照后端真实契约处理。

```tsx
import { NG } from '@newgrand/udp-ui';
import {
  DesignReportTable,
  type DesignReportTableApiExecutor
} from '@newgrand/udp-report-table';

const apiExecutor: DesignReportTableApiExecutor = {
  previewReportData: async (payload) => {
    const result = await NG.request.body({
      url: '/reportcenter/reportDesign/previewReportData',
      data: payload
    });

    // 返回平台信封 { Code, Msg, Data }。
    // 如接入自有计算服务，使用业务实际地址，并在这里适配响应。
    return result;
  }
};

<DesignReportTable
  id={reportId}
  name="财税报表"
  financeTax
  apiExecutor={apiExecutor}
/>;
```

财税业务参数可在执行器内增加到请求中，字段名和服务端接收方式由双方约定。不要通过替换标准字段来表达计算范围，例如将 `sheetKey` 设置为 `"all"`；组件没有这一约定。

### 1.2 完整请求协议示例

计算入参是在保存结构上增加 `reportName`、`sheetKey` 和 `queryParamList`。其中 `schema`、`globalProperty`、`sheetProperty`、`querySetting` 是 JSON 字符串。

下面是包含两张工作表的最小协议示例。实际接入应使用组件生成的完整设计，保留布局、样式、合并、字体等字段。`A1+B1` 仅用于说明公式与结果的关系，实际公式语法由业务计算引擎规定。

```ts
import { buildPreviewReportDataPayload } from '@newgrand/udp-report-table';

const requestExample = buildPreviewReportDataPayload({
  reportId: 'R001',
  reportName: '财税报表',
  dataSetIds: [],
  globalProperty: {},
  sheetProperty: [
    { sheetKey: '0', sheetProperty: {} },
    { sheetKey: '1', sheetProperty: {} }
  ],
  sheetKey: '0',
  querySetting: [
    { sheetKey: '0', queryConfig: [] },
    { sheetKey: '1', queryConfig: [] }
  ],
  queryParamList: [],
  sheets: [
    {
      sheetKeyId: 'sheet-001',
      sheetKey: '0',
      sheetName: '报表1',
      globalSettings: { rows: 6, cols: 4 },
      cells: [
        {
          row: 0, col: 0, cellType: 'text',
          cellData: { value: 1000 }
        },
        {
          row: 0, col: 1, cellType: 'text',
          cellData: { value: 234.5 }
        },
        {
          row: 0, col: 2, cellType: 'financeTax',
          cellData: { value: 'A1+B1' }
        }
      ]
    },
    {
      sheetKeyId: 'sheet-002',
      sheetKey: '1',
      sheetName: '报表2',
      globalSettings: { rows: 6, cols: 4 },
      cells: [
        {
          row: 0, col: 0, cellType: 'text',
          cellData: { value: 123.45 }
        }
      ]
    }
  ]
});
```

构造函数会将 `sheets` 序列化为 `requestExample.schema`。请求体包含全部工作表设计；顶层 `sheetKey` 表示当前工作表在保存结构中的序号字符串。`sheetKeyId` 保存原设计工作表键，与该序号不是同一字段。

### 1.3 完整返回协议示例

执行器返回 `{ Code, Msg, Data }`，`Code === 200` 时组件认为请求成功。`Data` 必须是工作表数组，不能直接返回字符串或 `{ sheets: [...] }` 包装对象；业务原始响应如果采用其他结构，需要在执行器中转换。

```ts
const responseExample = {
  Code: 200,
  Msg: '计算成功',
  Data: [
    {
      sheetKey: '0',
      sheetName: '报表1',
      globalSettings: { rows: 6, cols: 4 },
      cells: [
        {
          row: 0, col: 0, cellType: 'text',
          className: 'htRight htMiddle',
          cellData: { value: 1000 },
          formatData: '1,000.00'
        },
        {
          row: 0, col: 1, cellType: 'text',
          className: 'htRight htMiddle',
          cellData: { value: 234.5 },
          formatData: '234.50'
        },
        {
          row: 0, col: 2, cellType: 'text',
          className: 'htRight htMiddle',
          cellData: { value: 1234.5 },
          formatData: '1,234.50'
        }
      ]
    },
    {
      sheetKey: '1',
      sheetName: '报表2',
      globalSettings: { rows: 6, cols: 4 },
      cells: [
        {
          row: 0, col: 0, cellType: 'text',
          className: 'htRight htMiddle',
          cellData: { value: 123.45 },
          formatData: '123.45'
        }
      ]
    }
  ]
};
```

返回中的 `cellData.value` 是原始值，`formatData` 是用于显示的内容。多表响应应保持与请求相同的工作表顺序和 `sheetKey`，并返回各结果表完整的 `cells` 和布局配置；当前预览实现按工作表序号从数组取数据。

该示例说明组件要求的返回结构，不表示已验证现有平台接口实际会返回两张表。

### 1.4 结果显示与公式保留

请求成功后，组件保留原设计表，在同一区域另行展示只读 `ReportTable`，并将返回的数组作为计算结果工作表。原设计公式仍保存在设计数据中，计算结果不会写回并覆盖公式。

- 计算状态不可编辑或保存。
- 点击“关闭计算”后，恢复原设计及公式。
- 计算结果包含多张表时，用户可通过工作表标签查看；标签切换不再次发起计算请求。
- 设计器 `reportApi` 始终绑定原设计表，计算状态下读取它不能当作读取计算结果。
- 业务需要保留或继续使用计算结果时，应在执行器中保留响应数据；原始计算值读取 `cellData.value`。
- `ref.current.getValue()` 在计算状态下返回 `null`，需要关闭计算后读取原设计的保存结构。

### 1.5 四种计算范围分别是否支持？

| 计算范围 | 当前源码能确认的内容 | 调用方式及待确认项 |
| --- | --- | --- |
| 当前工作表 | 已有计算预览入口，请求带当前 `sheetKey` | 点击“计算”进入 `previewReportData`。现有后端是否仅算当前表、如何使用 `sheetKey`，需要确认 |
| 全部工作表 | 请求包含全部设计；前端能够展示多表返回 | 后端可从 `JSON.parse(payload.schema)` 取得全部表。现有接口是否实际计算全部表，需要确认；不能直接答复“已支持” |
| 单元格 | 没有现成的单元格范围计算 API | 标准计算入参没有用于限定范围的 `row`、`col`；需要另行确定前后端范围契约 |
| 选中区域 | 没有现成的选区范围计算 API | 标准计算入参没有 `range`；需要另行确定选区与计算接口的对接契约 |

组件没有公开的 `calculate(scope, range)` 方法。调用计算执行器或请求接口，并不等于组件提供了四种计算范围切换能力。

对于“全部工作表计算”，下一步应核对已有 `previewReportData` 后端是否按顶层 `sheetKey` 过滤、是否处理完整 `schema`、是否处理跨表公式依赖，以及实际返回几张工作表。仅执行 `JSON.parse(payload.schema)` 可以取得设计数据，不能自动完成计算。

## 2. 怎么获取选中的完整区域？

业务需要完整的起止行列，例如 B2 到 D6，而不只是当前单元格坐标。

公开 API `reportApi.selectCell(row, col, endRow, endCol)` 可以选择区域；`reportApi.getCurrentCell()` 只返回 `{ row, col }`。目前设计器的公开 `ReportTableMinApi` 没有 `getSelectedRange()` 或 `getSelectedRanges()`。

内部 `selectedCoords` 事件已经包含 `selectedRange.from` 和 `selectedRange.to`。在当前实现中，可将页面观察器订阅作为过渡接法：

```tsx
import { useEffect } from 'react';
import { NG } from '@newgrand/udp-ui';

// 在宿主 React 组件内订阅。
useEffect(() => {
  return NG.getPageObserver().subscribe((event) => {
    const range = event?.selectedRange;
    if (!range) return;

    const { from, to } = range;
    const selected = {
      startRow: Math.min(from.row, to.row),
      startCol: Math.min(from.col, to.col),
      endRow: Math.max(from.row, to.row),
      endCol: Math.max(from.col, to.col)
    };

    // 业务保存该范围，后续传给双方约定的范围计算接口。
    console.log(selected);
  }, 'selectedCoords');
}, []);
```

行列索引从 0 开始，结束坐标包含在范围内。选中 B2 到 D6 时：

```ts
{
  startRow: 1,
  startCol: 1,
  endRow: 5,
  endCol: 3
}
```

使用 `Math.min` / `Math.max` 可以处理反向拖选。该示例针对普通矩形单元格区域；整行、整列选择、多个不连续区域和多实例隔离还需要明确公共契约。当前事件来自内部页面观察器，且使用最后一个选区，不宜将它描述为正式、完整的公开范围 API。

如使用独立的 `ReportTable` 预览组件，其公开 ref 有 `getHotInstance()`，可通过返回的 `hotInstance.getSelectedLast()` 获取最后一个区域；这不代表 `DesignReportTable` 也公开了同名方法。

## 3. 单元格是否支持数值类型，格式与保存加载怎么处理？

### 3.1 手工输入与 API 写入

当前业务单元格类型包括文本、字段、表达式、财税、树、图片、图表等，尚未正式封装完整的独立数值类型。底层 Handsontable 的数值能力不能直接等同于报表组件已经完成数值编辑、格式与持久化支持。

| 操作 | 当前行为 |
| --- | --- |
| 在默认文本格手工输入 `123.45` | 文本编辑器产生字符串，读取为 `"123.45"` |
| `setCellData(row, col, 123.45)` | API 传入数字，读取可得到数字 `123.45` |
| `setCellData(row, col, '123.45')` | API 传入字符串，读取仍为字符串 |
| `getCellData(row, col)` | 读取底层值，不统一转换类型 |
| `getCellText(row, col)` | 将数据转换为字符串，不能当作格式化显示值的读取方法 |

```ts
const api = designerRef.current.reportApi;

api.setCellData(1, 1, 123.45);
const value = api.getCellData(1, 1);

console.log(value);        // 123.45
console.log(typeof value); // 'number'
```

金额、数量参与业务计算时，应使用原始数字。默认文本输入需要业务明确数值转换和空值处理规则；组件当前没有提供完整的数值输入校验契约。

### 3.2 显示千分位时，原始值是否仍是数字？

可以保留，前提是计算接口分别返回原始值与显示值：

```ts
{
  row: 1,
  col: 1,
  cellType: 'text',
  cellData: { value: 1234.5 }, // 原始数字
  formatData: '1,234.50'      // 显示字符串
}
```

预览的数据矩阵读取 `cellData.value`，渲染优先使用 `formatData`。因此显示 `1,234.50` 时，底层仍可保留数字 `1234.5`，供业务计算使用。

如果接口只返回字符串 `"1,234.50"` 作为原始值，组件不会自动还原成数字。也不能通过设计器的 `reportApi` 读取隐藏设计表来取得这份预览结果。

### 3.3 小数位、千分位和负数格式

字段格与普通表达式格的属性面板已有“格式化”和“保留小数位”配置，规则保存在 `cellData.format` 和 `cellData.formatValue` 中。

| 显示要求 | `cellData.format` | `cellData.formatValue` |
| --- | --- | --- |
| 千分位、两位小数 | `###,##0.00` | `2` |
| 不使用千分位、两位小数 | `#####0.00` | `2` |
| 千分位、不显示小数 | `###,##0` | `0` |
| 百分比 | `percent` | 小数位数，例如 `2` |

除属性面板外，也可以通过单元格属性 API 配置。以下示例适用于字段格或普通表达式格，并保留原 `cellData` 中的字段、公式等内容：

```ts
const api = designerRef.current.reportApi;
const current = api.getCellProp(row, col, 'cellData');
const original = current && typeof current === 'object' ? current : {};

api.setCellProp(row, col, 'cellData', {
  ...original,
  format: '###,##0.00',
  formatValue: 2
});

const configured = api.getCellProp(row, col, 'cellData');
// configured.format / configured.formatValue 为配置值。
```

这些字段描述格式规则，实际格式化结果需要计算接口按规则生成 `formatData`。普通文本格没有同样的格式面板；财税类型当前明确移除了面板中的 `format` 和 `formatValue` 配置，不能将字段/普通表达式的格式能力直接描述为财税面板已有能力。

目前未查到负数括号、负数红色等独立配置项。业务接口可以保留 `cellData.value: -1234.5`，并根据业务要求返回 `formatData: '-1,234.50'` 或 `formatData: '(1,234.50)'`；这属于业务格式化方案，组件没有提供完整的负数格式配置功能。

### 3.4 保存再加载能否保留类型和格式？

普通非零数字，例如 `123.45`，可通过保存结构中的 `cellData.value` 保留为 JSON 数字。字段格和普通表达式格的格式规则进入 `cellData` 保存，字段数字格式还有序列化、回显处理。业务后端需保留 JSON 的值类型和字段，不能统一将数字转为字符串。

当前仍有三个边界：

1. `type` 和 `numericFormat` 不在报表单元格保存字段列表中，直接设置底层运行时属性不能当作完整的数值类型持久化方案。
2. 计算响应中的 `formatData` 属于预览结果，计算态不能直接保存；持久格式应使用设计中的格式规则，并由计算接口重新生成显示值。
3. 前端保存助手验证发现：默认文本样式下，数值 `0` 会被按空值处理，测试得到空 `cells`。该边界需要修复并验收，当前不能承诺完整数值保存加载闭环。

第三项是源码及保存助手层面的验证结果，未覆盖所有浏览器样式和编辑路径。已有数字赋值能力也不代表手工输入已经具有数值类型。

## 待平台确认与支持计划

截至本次核对，未在当前组件库和相关工程记录中查到上述缺口的明确交付日期。以下为需要平台确认的事项，不代表已承诺的支持计划：

- 确认现有 `previewReportData` 的当前表/全部表计算行为，以及跨表公式依赖处理方式。
- 确认单元格和选区计算是否有现成后端能力；若无，明确范围入参、结果结构和排期。
- 将完整选区读取封装为公开 API，明确 0 起始索引、反向选择、多选、整行整列及实例归属。
- 补齐数值编辑、数值读取、格式配置与保存加载契约，处理数值 `0` 保存边界，并明确财税类型的格式能力。
- 明确负数格式的配置方式，以及各缺口的支持版本和交付日期。

既有 ADR 明确：第一阶段保留公式字段，计算沿用服务端预览/打印链路；完整前端公式引擎需在实际调用样例和计算契约明确后另行立项。
