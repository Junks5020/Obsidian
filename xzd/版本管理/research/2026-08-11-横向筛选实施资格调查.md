# 横向筛选实施资格调查

相关：[[work-items/report-table-functional-sync-refactor/spec]] · [[work-items/report-table-functional-sync-refactor/issues/05-调查轴向无关筛选]] · [[report-table-ADR-0001-跟随上游功能型同步]]

## 结论

本轮**不实施轴向无关筛选计算，也不建立后续实现规格**。横向计算具有明确的上游功能血缘，但当前用户入口不可达，且双基线缺少足够的横向行为 fixtures；三道实施门槛只通过一项。

| 门槛 | 结论 | 证据 |
| --- | --- | --- |
| 可达性 | 不通过 | 目标 `filterRender/render.ts:42` 与固定上游同文件 `:41` 都以 `cellProperties.expand === 'right'` 禁用筛选按钮；上游响应 mock 同时在 cell 顶层和 `filterRange` 中记录展开方向，说明该 guard 会拦截横向 cell 的用户点击。 |
| 功能血缘 | 通过 | 上游 `c93a206c` 首次以 `feat: 报表筛选支持横向筛选` 引入；多条件重写 `8426f174` 明确禁用横向入口；`e9e41b78` 又以 `update: 支持横向筛选（不支持排序）` 恢复列向计算。`e9e41b78` 是固定基线 `6636f93207d701517e78de9af46cc8dd57548fda` 的祖先。 |
| 行为基线 | 不通过 | 固定上游没有横向筛选行为 fixture；目标仅从 `renderTableByFilter` 直接覆盖一次单条件确认和重置。没有从可见 UI 入口开始的 fixture，也没有多条件横向筛选、横向重置与持久隐藏列叠加的完整 parity fixture。通用 visibility owner 并集测试不能替代横向提交行为基线。 |

## 调用路径

当前可见入口到阻断点：

1. `preview/plugins/textRender.tsx` 发现 `cellProperties.filterRange`，调用 `createFilterComponent`。
2. `preview/plugins/filterRender/render.ts` 创建按钮；横向 cell 在 click 之前被 `button.disabled` 阻断。

若未来入口被明确启用，下游静态路径是：

1. `createFilterComponent` click → `filterRender/util.tsx::handleClick`。
2. `handleClick` 形成 `expand === 'right'` 的 range → `handleOpenFilterPopup`。
3. `FilterModal` 确认或重置 → `renderTableByFilter`。
4. `renderTableByFilter` → `commitFilter` → `calculateColumns`。
5. `getDataWithMutipledCondition_Col` 计算隐藏列 → reload → `setFilterHiddenColumns` → render。

目标现有直接调用测试只能证明第 4、5 步的单条件成功路径可以运行，不能证明用户可从第 1 步到达。

## 重新评估条件

同时满足以下条件时重新建立独立规格：

1. 固定上游或明确产品需求正式启用横向筛选按钮，并以真实响应证明 UI 能形成 `expand === 'right'`。
2. 上游提供或本地先建立横向单条件、多条件、重置和持久隐藏列叠加的 parity fixtures。
3. fixtures 从用户入口覆盖到列可见性的最终结果，并明确横向不排序语义。

本调查没有代码或测试产物，按 ticket 约束不创建空 Git 提交。
