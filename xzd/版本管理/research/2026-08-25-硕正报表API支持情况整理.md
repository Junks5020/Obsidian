## 一、总体结论

当前仓库主要提供以下能力：

- `@newgrand/udp-report-table` 报表设计器和报表预览组件。
- 报表设计、打印设计相关的业务请求和数据转换。
- `@newgrand/udp-ui` 中基于 Supcan 的 `PrintPlugin` 打印插件封装。
- Handsontable 提供的表格编辑、行列操作、单元格操作和工具栏能力。

当前未完成的部分：

- 原需求文档中的 15 个业务菜单路由不在本仓库中。
- 没有提供硕正原生 API 的同名兼容层。
- 没有公开 `REPORT_TOOL_BAR_FUNC`、`REPORT_LIMIT` 等原生常量。
- 公式计算、原生事件锁、工作表原生 API、打印页数 API 等能力没有对外提供。

需要特别区分：部分功能可以通过 Handsontable 或内部 `doFunc` 间接完成，但这不等同于对外兼容了硕正 API。

## 三、硕正原生 API 支持情况

状态说明：

- **已支持**：存在对外公开的同名 API，且有实现。
- **部分支持**：有内部实现或底层等价能力，但没有同名公开 API。
- **未支持**：没有发现对应实现或可确认的等价能力。

### 3.1 核心生命周期与数据

| API | 状态 | 当前情况 |
| --- | --- | --- |
| `build(fmt)` | 部分支持 | `PrintPlugin` 内部调用 Supcan `Build`，未对外暴露。 |
| `getFileXML()` | 未支持 | 未发现实现。 |
| `setBatchFunctionURL(url)` | 未支持 | 未发现实现。 |
| `setSource(url)` | 部分支持 | `PrintPlugin` 内部调用 `SetSource`，未对外暴露。 |
| `setParasEx(params)` | 部分支持 | 初始化时内部调用 `SetParasEx`，未对外暴露。 |
| `setHttpHeadProp(key, value)` | 部分支持 | 初始化时设置 Authorization 请求头，未对外暴露。 |
| `setAutoCalc(config)` | 未支持 | 仅发现内部 `Calc` 调用，没有自动计算配置 API。 |
| `addUserFunctions(funcs)` | 未支持 | 未发现实现。 |
| `setRedrawAble(able)` | 未支持 | 未发现实现。 |

### 3.2 界面显示与交互

| API | 状态 | 当前情况 |
| --- | --- | --- |
| `callFunc(funcName, opts)` | 部分支持 | `PrintPlugin` 内部通过 `doFunc` 调用 Supcan 函数，未作为公共 API 暴露。 |
| `setSeparateView([row, col])` | 未支持 | 未发现同名或明确等价 API。 |
| `setToolbarItemStatus(key, state, value)` | 未支持 | 工具栏有 React 状态刷新，但没有该 API。 |
| `setProp(opts)` | 部分支持 | 打印模板加载时内部调用 `SetProp`，未对外暴露。 |
| `getProp(propsKey)` | 未支持 | 未发现实现。 |

## 四、工具栏常量支持情况

需求中的 `REPORT_TOOL_BAR_FUNC` 常量没有定义。当前是自定义 React 工具栏 ID。

### 有功能对应物

- `PRINT_SETTING`：对应 `print_setting`。
- `PRINT_PREVIEW`：对应 `ribbon_preview` 或打印设计中的 `print_preview`。
- `UNDO` / `REDO`：对应 `undo` / `redo`。
- `CELL_MERGE`：对应 `merge_cells` 和右键菜单合并。
- 行列插入、删除、行高、列宽：对应自定义工具栏和右键菜单。
- 导入、导出：对应 `report_import`、`report_export`。

## 五、报表权限常量

需求中的 `REPORT_LIMIT` 没有定义，以下权限没有兼容实现：

- `FORMULA`
- `NON_FORMULA`
- `WORKSHEET_ADD_AND_DEL`
- `ROW_CLO_ADD`

当前只有组件级的 `readOnly` 和设计器级的 `isView`，不能替代上述细粒度权限控制。

实现位置：

限制：该插件仍然依赖 `/NG3RW/supcan/dynaload.js` 和 Supcan 浏览器运行环境，因此属于旧引擎封装，不是底层替换。
