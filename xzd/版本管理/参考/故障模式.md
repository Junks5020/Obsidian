# Bug Patterns

## Configuration normalization at component boundaries

- Pattern: External metadata can arrive as a scalar, an array, or an empty/invalid value, while the component filters UI options only for one shape.
- Check: Normalize the boundary value first, support both semantic IDs and protocol values when required, and test empty plus mixed-valid configurations.
- Avoid: Do not let a truthy scalar or empty array silently become an empty option list when the component has a safe default.

## Umi generated module cannot be resolved

- Pattern: A dependency cannot resolve an import under `@@/*`, while the corresponding Umi plugin is configured.
- Check: Confirm the alias target in `src/.umi/tsconfig.json`, verify the generated module exists, then run one clean Umi prepare/compile cycle.
- Avoid: Do not add duplicate aliases, patch dependency imports, or install another plugin until a cold build also reproduces the failure.

## Expanded runtime data retains a one-row sibling range

- Pattern: A server expands one configured cell into multiple runtime rows, but non-expanding sibling columns retain their original one-row range metadata.
- Check: Compare the authoritative expanding column with sibling columns in the real API response; normalize only within the same contiguous header/data block and verify that target-column data exists through the expanded end row.
- Avoid: Do not require sibling `expand` values to be identical, and do not model every vertical field as `expand: "down"` in tests when real siblings use `expand: "none"`.

## Preserve independent invariants when removing composite behavior

- Pattern: Feature-specific behavior is colocated with unrelated safeguards such as virtualization, instance registration, cleanup, and visual metadata hooks.
- Check: Classify removed code by responsibility, then recheck rendering bounds, imperative-instance ownership, unmount cleanup, shared metadata, and branch-specific children.
- Avoid: Do not delete one contiguous component block merely because its primary feature is being removed; add assertions for both the removed behavior and every invariant that must remain.

## Normalize design-time fields at runtime adapters

- Pattern: Designer schemas and runtime query items use different field names for the same value; spreading the design object yields a valid-looking runtime object whose value is later filtered as empty.
- Check: Compare persisted and runtime contracts field by field, especially fallback paths that bypass the normal API shape. Test system values and user-entered defaults separately.
- Avoid: Normalize the runtime contract at the adapter boundary, and preserve explicitly persisted runtime fields, including `null`, rather than applying fallback with nullish coalescing.

## 区分缺失的运行态值与显式清空

- 模式：接口同时存在持久化字段 `defaultValue` 和运行态字段 `value`，直接使用空值合并或真值判断会把用户显式清空的值重新替换为默认值。
- 检查：只在 `value` 属性不存在时回退，并分别覆盖属性缺失、`undefined`、`null`、空字符串、`0` 和 `false`。
- 避免：不要使用 `value ?? defaultValue` 或 `value || defaultValue` 表达这个兼容契约。

## 分离式表单和表格缓存的保存边界

- 模式：弹窗右侧表单编辑左侧选中行，保存逻辑却直接读取表格缓存，最后一次表单变更可能尚未进入请求数据。
- 检查：确认保存和切换行时显式读取当前表单值并提交到选中行；用“表单值比表格缓存新”的场景覆盖保存边界。
- 避免：不要把逐字段变更通知当成可靠的保存契约。
