# 移动端附件选择与文件上传回归测试

对应 [[../变更记录/BUG-20261008-001-mobile-attachment-picker-upload-backport]]，验证本次移植提交 `532941e0918f89044545b06b3d0c8d769374e428` 的有效源码。脚本位于同目录 `移动端附件选择与文件上传回归测试.cjs`，不进入组件库 Git 提交。

## 执行

在已检出该移植提交、具备仓库依赖的工作区执行：

```powershell
node 'C:\Users\jinxu\workspace\obsidian\代码提交记录\ng-design\测试用例\移动端附件选择与文件上传回归测试.cjs' 'C:\path\to\ng-design'
```

脚本通过给定工作区加载 TypeScript、React、React DOM、ahooks 与 jsdom；直接执行该工作区的组件源码、来源配置与枚举。测试使用真实 React 18 状态更新和点击事件；UI 外壳、平台 API、文件输入的 `click()`、上传接口与延迟关闭定时器被替换，不访问服务器。

## 覆盖与结果

2026-10-08：22/22 通过。

| 场景 | 用例数 | 核对结果 |
| --- | --- | --- |
| Android、iOS、鸿蒙、微信与带空白平台值的文件来源 | 5 | 支持平台显示文件来源 |
| H5、钉钉、未给平台值 | 3 | 默认、自定义 `accept=['file']` 与空 `accept` 均不显示原生文件来源 |
| 取消、空返回、失败、缺少路径与 Promise 拒绝 | 6 | 点击事件内打开一次选择器；关闭弹层后不重复打开，不上传、不出现上传进度 |
| 原始文件名、元数据路径、路径文件名回退 | 3 | 路径与名称保持正确，普通文件 MIME 为 `application/octet-stream`，仅上传一次 |
| H5 文件单选、多选与连拍 | 3 | 在点击事件内设置 `accept`、`multiple` 并打开一次；弹层关闭不重复打开 |
| H5 签名 | 1 | 保留弹层关闭后调用签名接口 |
| H5 上传回调缺少载荷、文件或文件列表 | 1 | 不抛出异常，不创建上传进度 |

完整构建、Prettier、补丁空白检查与提交钩子也通过，见变更记录。此脚本没有验证真实操作系统文件选择器、WebKit 的用户激活规则、原生文件适配器与真实后端上传。
